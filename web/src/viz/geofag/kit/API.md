# Geofag-kit: kort API-oversikt

Generert fra JSDoc (første avsnitt) for alt som eksporteres fra `geofag/kit`. Komponentene har en linje med props (`navn?` er valgfri, `= verdi` er standardverdien, og typen står når den ikke er number, string eller boolean), funksjonene har parameterne og det de gir (→), og typene står til slutt i hvert avsnitt. Les kildefila bare for komponentene du faktisk bruker (props og ankerpunkt står i JSDoc der).
Importer fra `../kit`. Bilder av alt: `viz-preview.html?galleri=geo-alle`, eller én familie med `?galleri=geo-<familie>` (kart, landskap, monstre, snitt, stein, tektonikk, vann).
Lag fila på nytt fra web/ med `node scripts/kit-api.mjs src/viz/geofag/kit > src/viz/geofag/kit/API.md`.

## Fra det felles kit-et (`viz/kit`)
Alt fra `viz/kit` følger med (props og bruk står i viz/README.md og i kildefilene der): `VIZ`, `VizLayout`, `Controls`, `Slider`, `Segmented`, `Toggle`, `Toolbar`, `useTextScale`, `Figure`, `Readouts`, `Readout`, `Formula`, `FormulaLine`, `Sub`, `Sup`, `Explain`, `Legend`, `scaleLinear`, `niceTicks`, `linePath`, `sample`, `Arrow`, `Label`, `Block`, `Ground`, `Plot`, `Dot`, `Spring`, `TSub`, `TSup`, `Boundary`, `useSimClock`, `PlayControls`, `fmt`, `fmtUnit`, `fmtSci`, `superscript`, `clamp`, `G_EARTH`, `useSvgId`, `Txt`, `WorkedExample`.

## Fra `viz/kjemi/kit`
- **seededRandom**(seed) → `() => number` (random.ts): Enkel tallgenerator med fast frø (mulberry32). Gir tall i [0, 1).
- **placeParticles**(box, groups, seed?, gap?) → `PlacedParticle[]` (random.ts): Sprer partikler tilfeldig (men alltid likt for samme frø) i et rektangel uten at de overlapper, så langt det er plass. Partiklene holder seg helt inne i boksen. Gruppene blandes, så ioner av ulik type ikke klumper seg.
- **jiggle**(p, t, amplitude) → `{ x: number; y: number }` (random.ts): Liten, jevn «varmebevegelse» for en partikkel ved tiden t (sekunder): forskyvning på høyst `amplitude` i hver retning. Deterministisk, så samme t alltid gir samme bilde. Bruk med `useSimClock`.
- **Select** (controls.tsx): Nedtrekksliste med synlig etikett, f.eks. «Stoff: [vann (H₂O) ▾]». Bruker appens vanlige `<select>`-stil.
  - Props: `label`, `value: T`, `options: { value: T; label: string }[]`, `onChange: (value: T) => void`
- **useContainerTextScale**(vbWidth?) → `readonly [React.RefObject<T | null>, number]` (controls.tsx): Tekstskaleringen en `<Figure>` med denne viewBox-bredden vil få når den fyller elementet `ref` peker på (samme regel som Figure bruker: 1 på PC, ca. 1,8 på mobil). Bruk den til å velge viewBox-høyden før figuren tegnes, så teksten får plass på mobil:
- **Formel** (Formel.tsx): Formel i vanlig HTML med `<sub>`/`<sup>`.
  - Props: `f: string | ParsedFormula`, `state: boolean | State = true`, `coef?`
- **TFormel** (Formel.tsx): Formel inne i SVG-tekst (`<text>`, `<Txt>`, `<Label>`), med kit-ets TSub/TSup.
  - Props: `f: string | ParsedFormula`, `state: boolean | State = true`, `coef?`
- **Reaksjon** (Formel.tsx): Reaksjonslikning i vanlig HTML: «2 H₂ + O₂ → 2 H₂O».
  - Props: `r: string | Reaction`, `states = true`
- **TReaksjon** (Formel.tsx): Reaksjonslikning inne i SVG-tekst.
  - Props: `r: string | Reaction`, `states = true`
- **Begerglass** (beger.tsx): Begerglass med tut, væske, menisk og eventuelle volummerker.
  - Props: `x`, `y`, `w`, `h`, `level`, `liquid = KJEMI.liquid`, `children?: ReactNode | ((liquid: Box) => ReactNode)`, `marks?: { level: number; label?: string }[]`, `label?`
- **mixColor**(a, b, t) → `string` (colors.ts): Blanding av to farger (også CSS-variabler) med CSS `color-mix`: t = 0 gir `a`, t = 1 gir `b`. Brukes f.eks. når en indikator skifter farge gradvis.
- **fmtSig**(v, sig?) → `string` (format.ts): Tall med `sig` gjeldende siffer (standard 3), på standardform når det er veldig stort eller lite: 0,555 · 18,0 · 100 · 3,34 · 10²³ · 1,66 · 10⁻⁴. Ugyldige tall gir «–».

## Fra `viz/biologi/kit`
- **Etikett** (felles.tsx): Etikett med tynn strek til det den peker på, som i lærebokfigurer: `<Etikett x={mito.x} y={mito.y} lx={620} ly={80}>Mitokondrie</Etikett>` Teksten vokser på mobil (som `<Txt>`), så sett av god plass til den.
  - Props: `x`, `y`, `lx`, `ly`, `children`, `anchor?: 'start' | 'middle' | 'end'`, `color?`, `strong?`, `size = 0.85`, `noDot?`
- **Forvalg** (controls.tsx): Rad med forhåndsvalg der ingen eller én er valgt, f.eks. sykdommer som setter R₀-glidebryteren. Til forskjell fra `<Segmented>` kan `value` være null (når glidebryteren er flyttet til en verdi som ikke er et forhåndsvalg).
  - Props: `label`, `options: ForvalgOption<T>[]`, `value: T`, `onPick: (value: T) => void`
- **PlayBar** (controls.tsx): Som `<PlayControls>` i kit-et, men tida vises med egen tekst og enhet, f.eks. «dag 34» eller «t = 6,5 timer», fordi klokka i biologi ofte teller døgn eller år og ikke sekunder. `time` er ferdig formatert tekst.
  - Props: `clock: SimClock`, `time`
- **fmtPct**(share, decimals?) → `string` (format.ts): Andel (0–1) som prosent med hardt mellomrom: 0.456 → «46 %», med `decimals` = 1 → «45,6 %». Svært små andeler som ikke er null vises som «< 1 %» (eller «< 0,1 %»), så de ikke ser ut som null.
- **fmtCount**(n) → `string` (format.ts): Store antall med mellomrom som tusenskille: 2097152 → «2 097 152». Over en milliard: standardform.
- **solveOde**(f, y0, { tMax, dt, t0, nonNegative, maxSteps }) → `OdeSolution` (modeller.ts): Løser y′ = f(t, y) fra t0 til tMax med RK4 og fast steg.

## typer.ts
Typer som flere deler av geofag-kit-et deler. Mønstrene (`monstre.tsx`) og bergartstabellen (`bergarter.ts`) bruker samme liste, så de kan skrives hver for seg.

- **MONSTER_IDS** (`readonly MonsterId[]`): Alle mønstrene i fast rekkefølge (til galleriet og testene).
- Typer: `MonsterId = 'granitt' | 'gneis' | 'basalt' | 'gabbro' | 'diabas' | 'sandstein' | 'siltstein' | …`

## colors.ts
Faste farger for geofagvisualiseringene. Verdiene er CSS-variabler (`--geo-*` i geofag.css, som kit-ets index.ts laster) og fungerer i både lyst og mørkt tema, også med fagtemaet «Fjell». Bruk aldri egne fargekoder i komponentene.

- **GEO**: Alle geofagfargene. Flater er `{ fill, line }` (GeoPaint), linjer og skalaer er strenger med `var(--geo-…)`: `<path d={…} fill={GEO.magma.fill} stroke={GEO.magma.line} /> <ForceArrow … color={GEO.nedbor} label="Nedbør" /> <rect fill={GEO.tid.devon} />  ·  GEO.hoydelag[0..5]  ·  GEO.gehalt[0..4]  ·  GEO.fare[0..3]` Bergartene ligger i `GEO.bergart[id]` (samme farger som mønstrene i `LagMonstre`).
- **bergartFarge**(id) → `GeoPaint`: Fyll og kant for et mønster eller en bergart (samme som `GEO.bergart[id]`).
- **gehaltFarge**(andel) → `string`: Farge for en andel 0–1 av høyeste gehalt (5 trinn). Ugyldige tall gir laveste trinn.
- **fareFarge**(niva) → `string`: Farge for faregrad 0–3 (avrundet og begrenset). Ugyldige tall gir laveste grad.
- **hoydelagFarge**(hoyde, min, max) → `string`: Høydelagsfarge for en høyde i en skala fra `min` til `max` (6 like trinn).
- **tidFarge**(navn) → `string`: Fargen til en tidsenhet (`GEO.tid[navn]`), eller en nøytral farge når navnet ikke finnes.
- Typer: `GeoPaint { fill, line }`, `TidFarge = 'prekambrium' | 'hadeikum' | 'arkeikum' | 'proterozoikum' | 'eoarkeikum' | …`

## felles.tsx
Små felles hjelpere for geofagfigurene: hvor mye symboler og streker skal vokse på mobil, og hvor høy viewBox-en bør være når teksten blir større. Bygd på `useSceneScale` og `useStrokeScale` i scene-kit-et, så geofag og scenene vokser likt.

- **useGeoScale**() → `number`: Hvor mye små figurer (krystaller, korn, isotopprikker, symboler, mønstre) bør forstørres for å kunne sees: 1 på PC, ca. 1,5 på telefon (k = max(1, 0,85 · f), der f er tekstskaleringen). Bare inne i en `<Figure>`. Gang dine egne avstander med den også, ellers overlapper symbolene på mobil.
- **useGeoStroke**() → `number`: Faktor for strektykkelser i mønstre, koter og konturer: 1 på PC, ca. 1,35 på telefon (max(1, 0,75 · f)), så tynne streker ikke forsvinner når figuren skaleres ned. Bare inne i en `<Figure>`.
- **geoHoyde**(f, H) → `number`: Høyden på viewBox-en for en figur med grunnhøyde `H` når teksten vokser med faktoren `f` (fra `useContainerTextScale`): H + 260 · (f − 1). Grafer, kart og snitt blir da høyere på mobil, så aksetitler og etiketter får plass. Ugyldig eller for liten `f` behandles som 1. `` const [ref, f] = useContainerTextScale<HTMLDivElement>(); <div ref={ref}><Figure viewBox={`0 0 800 ${geoHoyde(f, 320)}`} …>…</Figure></div> ``

## monstre.tsx
Mønstre for bergarter, sedimenter og løsmasser, som på geologiske kart og i PDF-malen «Atlas»: prikker for sandstein, murstein for kalkstein, små kryss for granitt, v-er for basalt … Ett SVG-mønster per `MonsterId` (typer.ts), med bakgrunn og strek fra `GEO.bergart[id]`, så mønstrene følger lyst og mørkt tema.

- **MONSTER_NAVN** (`Record<MonsterId, string>`): Navnet på hvert mønster til forklaringer og knapper (bokmål, stor forbokstav bare først).
- **LAG_MONSTRE_ID**: Standard-id for mønstrene når figuren bare har én `<LagMonstre />` og ingen id.
- **lagFyll**(type, id?) → `LagFyll`: Fyll (`url(#<id>-<type>)`) og strekfarge for et lag med mønsteret `type`. `id` må være den samme som på `<LagMonstre id>` i figuren (standard `LAG_MONSTRE_ID`). Strektykkelsen på konturen: `useLagMonstre().kontur`.
- **useLagMonstre**(prefiks?) → `LagMonstreSett`: Unik id for mønstrene i én figur, så flere figurer (eller flere kit-komponenter) på samme side ikke bruker hverandres mønstre. Bruk den i alle gjenbrukbare komponenter; kapitler med én figur kan bruke `<LagMonstre />` og `lagFyll(type)` uten id. Bare inne i en `<Figure>`.
- **LagMonstre**: Én `<defs>` med et mønster per bergart, sediment og løsmasse (`MonsterId`), som på geologiske kart. Tegnes én gang i figuren, før lagene som bruker den. Mønsteret vokser med `useGeoScale` på mobil, strekene med `useGeoStroke`. Memoisert, så den tegnes ikke på nytt for hver ramme i en animasjon.
  - Props: `id = LAG_MONSTRE_ID`, `skala = 1`, `bare?: readonly MonsterId[]`
- **LagFlate**: Ett lag i et snitt: formen fylt med mønsteret, kontur i mønsterets strekfarge og (standard) svak toning med lys ovenfra, som i en lærebokillustrasjon. Krever `<LagMonstre id={monstre} />` i samme figur. Ankerpunkt: ingen egen plassering; formen (`points` eller stien `d`) er i figurens koordinater. `<LagFlate points={[[0, 200], [800, 180], [800, 260], [0, 260]]} type="sandstein" monstre={lag.id} />`
  - Props: `d?`, `points?: readonly (readonly [number, number])[]`, `type: MonsterId`, `monstre = LAG_MONSTRE_ID`, `lys = true`, `utenKontur?`, `dim?`, `children?`
- Typer: `LagFyll { fill, stroke }`, `LagMonstreSett { id, fyll, kontur }`, `LagMonstreProps`, `LagFlateProps`

## geotid.ts
Geologisk tid: tidsskalaen etter ICS-kartet, oppslag (`periodeVed`), jordas historie som ett døgn (`tilDognet`) og aldre skrevet på norsk (`fmtAlder`). Ren logikk uten React.

- **GEOLOGISK_TID** (`readonly TidsIntervall[]`): Hele tidsskalaen etter ICS-kartet versjon 2023/09: eoner, eraer, perioder (også i proterozoikum) og epokene i kenozoikum, hvert nivå sortert fra eldst til yngst. Aldre i millioner år. Hadeikum har ingen eraer, og arkeikum har ingen perioder.
- **JORDAS_ALDER**: Jordas alder i millioner år (basen i hadeikum).
- **PREKAMBRIUM** (`TidsIntervall`): Prekambrium: den uformelle samlebetegnelsen på alt før kambrium (hadeikum, arkeikum og proterozoikum, omtrent 88 % av jordas historie). Ikke med i `GEOLOGISK_TID`, så nivåene der er sammenhengende; bruk den til ett bredt bånd på en tidslinje. Fargen er `GEO.tid.prekambrium`.
- **intervaller**(niva) → `TidsIntervall[]`: Alle intervallene på ett nivå, fra eldst til yngst.
- **tidsintervall**(id) → `TidsIntervall | null`: Intervallet med denne nøkkelen, eller null.
- **intervallVed**(alder, niva) → `TidsIntervall | null`: Intervallet på nivået `niva` som alderen (millioner år) ligger i, eller null (negativ alder, eldre enn jorda, ugyldig tall, eller ingen inndeling på det nivået, som perioder i arkeikum). En alder akkurat på en grense hører til det yngre intervallet, fordi grensen er basen til det: 66 er paleogen, ikke kritt. Alder 0 er i dag.
- **periodeVed**(alder) → `TidsIntervall | null`: Perioden alderen (millioner år) ligger i: `periodeVed(150)` gir jura. Der ICS-kartet ikke har perioder (arkeikum og hadeikum), gis eraen eller eonen i stedet, så det alltid finnes et bånd å vise. Null for alder under 0, over jordas alder eller et ugyldig tall.
- **varighet**(i) → `number`: Varigheten til et intervall i millioner år.
- **GEO_HENDELSER** (`readonly GeoHendelse[]`): Viktige hendelser i jordas historie (alder i millioner år, eldst først), til hendelsesmerkene på en `GeoTidslinje`: `<GeoTidslinje … hendelser={GEO_HENDELSER} />`. `omtrent` sier at alderen er omtrentlig, og `norsk` merker norsk geologi.
- **tilDognet**(alder, jordasAlder?) → `Dognstid | null`: Jordas historie (`jordasAlder` millioner år, standard 4567) presset sammen til ett døgn. Alder 4567 gir kl. 00.00.00, alder 0 gir kl. 24.00.00. Sekundene rundes av. Null for alder under 0, over jordas alder eller et ugyldig tall.
- **fraDognet**(sekunder, jordasAlder?) → `number | null`: Motsatt av `tilDognet`: sekunder etter midnatt (0–86 400) → alder i millioner år. Null utenfor døgnet.
- **fmtAlder**(millionerAar, valg?) → `string`: En alder i millioner år som norsk tekst: `fmtAlder(66)` → «66 millioner år», `fmtAlder(4567)` → «4,57 milliarder år», `fmtAlder(0.0117)` → «11 700 år», `fmtAlder(1)` → «1 million år». Skriver aldri forkortelsen «Ma» (bruk `kort` for «mill. år» i smale etiketter). Negative og ugyldige tall gir «–».
- Typer: `TidsNiva = 'eon' | 'era' | 'periode' | 'epoke'`, `TidsIntervall { id, navn, etikett, kort, symbol?, niva, start, slutt, usikkerhet?, omtrent?, forelder? }`, `GeoHendelse { alder, slutt?, tekst, omtrent, norsk? }`, `Dognstid { sekunder, timer, minutter, sek, forMidnatt, klokke, klokkeKort }`, `FmtAlderValg { siden?, desimaler?, enhet?, kort? }`

## datering.ts
Radiometrisk datering for geofag: isotopsystemene uran–bly, kalium–argon og C-14, hvor mye som er igjen, forholdet mellom datter og mor, alder fra et målt forhold og om oppvarming nullstiller klokka. Ren logikk uten React.

- **ISOTOPER** (`Readonly<Record<IsotopId, Isotopsystem>>`): Isotopsystemene uran–bly, kalium–argon og C-14 etter id: mor- og datterisotop, halveringstid (år), forgrening, mineralene med lukketemperatur, hva som kan dateres og måleområdet (år). Brukes av alle funksjonene i fila.
- **ISOTOP_IDS** (`readonly IsotopId[]`): Isotopsystemene i fast rekkefølge (til knapper og tester).
- **MARIN_RESERVOARALDER**: Havets reservoaralder for C-14 i år (omtrent 400 år for overflatehavet; langs norskekysten omtrent 400–450 år, Mangerud og Gulliksen 1975). Skjell og fisk ser så mye eldre ut enn trekull fra samme år, fordi havet blander inn gammelt karbon fra dypvannet.
- **gjenvaerende**(t, system) → `number | null`: Andelen av morisotopen som er igjen etter tiden `t` (år): 2^(−t/t½). `system` er et isotopsystem eller en halveringstid i år. Null for negativ tid, ugyldige tall eller halveringstid ≤ 0.
- **datterForhold**(t, system) → `number | null`: Forholdet radiogen datter / mor (D* / P) etter tiden `t` (år), med forgreningen til systemet: D* / P = f · (2^(t/t½) − 1). For K–Ar er f ≈ 0,105, så forholdet ⁴⁰Ar* / ⁴⁰K blir omtrent en tidel av det det ville vært om alt kaliumet ble til argon. Null for negativ tid eller ugyldige tall, og for så lange tider at forholdet ikke lenger er et endelig tall.
- **alderFraForhold**(forhold, system) → `number | null`: Alderen (år) fra et målt forhold datter/mor (D* / P): t = t½/ln 2 · ln(1 + (D* / P)/f). Null for negativt forhold eller ugyldige tall.
- **alderFraMengder**(datter, mor, system) → `number | null`: Alderen (år) fra mengdene datter og mor i en prøve (atomer, mol eller prosent, bare det er samme enhet). Null når det ikke er noen mor igjen (P = 0, alderen kan ikke bestemmes), ved negative mengder eller ugyldige tall.
- **alderFraRest**(andel, system) → `number | null`: Alderen (år) fra andelen av morisotopen som er igjen (0–1), slik C-14 måles: t = −t½ · log₂(andel). Med C-14 og 5730 år er dette en «forenklet alder» (ikke kalibrert). Null for andel ≤ 0 (alt er borte, alderen er ubestemt), andel over 1 eller ugyldige tall.
- **egnet**(system, alder) → `'for-ung' | 'egnet' | 'for-gammel' | null`: Om en alder (år) ligger i måleområdet til systemet: `'for-ung'` (for lite datter eller for lite henfall til å måle), `'egnet'` eller `'for-gammel'` (for lite mor igjen). Null for ugyldige tall.
- **konkordia**(t) → `{ x: number; y: number } | null`: Konkordiakurven for uran–bly: punktet (²⁰⁷Pb* / ²³⁵U, ²⁰⁶Pb* / ²³⁸U) etter tiden `t` (år). Zirkon som ikke har mistet bly, ligger på kurven; tap av bly drar punktet inn mot origo. Null for negativ tid eller ugyldige tall.
- **nullstilles**(system, toppTemperatur, varighet) → `Nullstilling[] | null`: Om en oppvarming til `toppTemperatur` (°C) i `varighet` (år) nullstiller klokka i hvert mineral systemet daterer. Forenklet modell: datterisotopen lekker ut med en tidskonstant som er 1 million år ved lukketemperaturen og endrer seg med temperaturen som diffusjon (Arrhenius), så tapet er 1 − e^(−varighet/τ). Zirkon tåler nesten all metamorfose, mens biotitt nullstilles allerede ved noen hundre grader.
- **tilsynelatendeAlder**(dannet, oppvarmet, andelTapt, system) → `number | null`: Alderen (år) et mineral ser ut til å ha i dag når det ble dannet for `dannet` år siden, ble varmet opp for `oppvarmet` år siden og da mistet andelen `andelTapt` (0–1) av datterisotopen. Helt nullstilt gir alderen til oppvarmingen, urørt gir dannelsesalderen, og delvis tap gir noe imellom. Null for ugyldige tall, oppvarming før dannelsen eller andel utenfor 0–1.
- **korrigerForReservoar**(alder, reservoaralder?) → `number | null`: C-14-alder (år) for et marint skjell, korrigert for havets reservoaralder. Null for ugyldige tall.
- Typer: `IsotopId = 'u-pb' | 'k-ar' | 'c-14'`, `DateringsMineral { mineral, lukketemperatur, aktiveringsenergi }`, `Isotopsystem { id, navn, kort, mor, datter, halveringstid, forgrening, maling, mineraler, materialer, maleomrade, andreKjede?, merknad }`, `Nullstilling { mineral, lukketemperatur, andelTapt, status }`

## mineraler.ts
Mineraler for geofag: mineralgruppene etter aniongruppe, silikatstrukturene, egenskapene som brukes til å bestemme et mineral i felt (hardhet, strek, glans, spalting, syre, magnet) og et filter som finner mulige mineraler fra observasjonene. Ren logikk uten React.

- **MINERALGRUPPER** (`Readonly<Record<MineralGruppeId, MineralGruppe>>`): Mineralgruppene etter aniongruppe (silikater, karbonater, oksider, sulfider, sulfater, halogenider, fosfater og grunnstoffer) etter id, med navn, aniongruppe og en kort beskrivelse til elevene.
- **SILIKATSTRUKTURER** (`readonly SilikatStruktur[]`): Silikatstrukturene fra øysilikater til rammesilikater: hvordan SiO₄-tetraedrene er koblet, hvor mange O-atomer hvert tetraeder deler, forholdet Si : O, eksempler og kjennetegn. Sortert fra minst til mest sammenkoblet.
- **GLANS_NAVN** (`Readonly<Record<Glans, string>>`): Norske navn på glansen («metallglans»).
- **STREK_NAVN** (`Readonly<Record<Strekfarge, string>>`): Norske navn på strekfargene.
- **MINERAL_TONER** (`readonly MineralTone[]`): Alle tonene i fast rekkefølge (til galleriet).
- **MINERALER** (`Readonly<Record<MineralId, Mineral>>`): Alle mineralene etter id, med gruppe, aniongruppe og egenskapene til mineralbestemmelse.
- **MINERAL_IDS** (`readonly MineralId[]`): Alle mineral-id-ene i fast rekkefølge (silikater først).
- **mineral**(id) → `Mineral | null`: Mineralet med denne id-en, eller null.
- **RISSETESTER** (`readonly Rissetest[]`): Redskapene i rissetesten (fingernegl, kobbermynt, kniv, glass, stålfil og strekplate) med omtrentlig hardhet på Mohs' skala, til `hardhetFraRissetester` og `muligeMineraler`.
- **MOHS_ABSOLUTT** (`readonly MohsTrinn[]`): Mohs' hardhetsskala fra talk (1) til diamant (10) med absolutt hardhet målt med sklerometer (omtrentlig), så en figur kan vise at trinnene ikke er like store.
- **hardhetFraRissetester**(tester) → `{ min: number; max: number } | null`: Hardhetsintervallet [min, maks] på Mohs' skala som passer med rissetestene. Risses mineralet, er det høyst like hardt som redskapet; risses det ikke, er det minst like hardt. Like hardhet regnes som mulig begge veier. Null når testene motsier hverandre eller et redskap er ukjent.
- **TETTHET_TOLERANSE**: Målefeilen som godtas på tetthet i `muligeMineraler` (g/cm³), som med kjøkkenvekt og målesylinder.
- **muligeMineraler**(obs, kandidater?) → `Mineral[]`: Mineralene i `MINERALER` som passer med alle observasjonene, i fast rekkefølge. Tomme observasjoner gir alle mineralene; motstridende rissetester gir en tom liste.

## kornstorrelse.ts
Kornstørrelse i geofag: kornklassene (leire, silt, sand, grus, stein, blokk), φ-skalaen, Hjulströms diagram (erosjon, transport og avsetning), synkefart, kornfordelingskurver fra sikteanalyse, persentiler (d10, d50, d60), graderingstall, krumningstall og sortering etter Folk og Ward. Ren logikk uten React.

- **KORNKLASSER** (`readonly Kornklasse[]`): Kornklassene etter NGU (grenser i mm), fra finest til grovest.
- **FINSTOFF_GRENSE**: Grensen mellom finstoff (silt og leire) og sand i mm: det som går gjennom den minste sikten i en sikteanalyse.
- **kornklasse**(d) → `KornklasseId | null`: Kornklassen til et korn med diameter `d` mm (grensene som i `KORNKLASSER`: 0,063 mm er sand, 2 mm er grus). d ≤ 0 eller ugyldig gir null.
- **phi**(d) → `number | null`: Kornstørrelsen på φ-skalaen (Krumbein): φ = −log₂(d i mm). Store korn har negativ φ (grus −1 til −6), fine korn positiv (leire over 9). d ≤ 0 gir null.
- **dFraPhi**(p) → `number | null`: Diameteren i mm for en φ-verdi: d = 2^(−φ). Ugyldig φ gir null.
- **HJULSTROM_EROSJON** (`readonly (readonly [number, number])[]`): Punkter på erosjonskurven: [diameter i mm, fart i m/s] (omtrentlig, avlest fra Hjulström 1935).
- **HJULSTROM_AVSETNING** (`readonly (readonly [number, number])[]`): Punkter på avsetningskurven: [diameter i mm, fart i m/s] (omtrentlig, avlest fra Hjulström 1935).
- **HJULSTROM_D** (`readonly [number, number]`): Kornstørrelsene diagrammet dekker, i mm. Korn utenfor behandles som endepunktene.
- **erosjonsfart**(d) → `number | null`: Erosjonsfarten fra Hjulströms diagram: vannfarten (m/s) som skal til for å rive løs et korn som ligger i ro på bunnen. Log–log-interpolasjon i `HJULSTROM_EROSJON` (omtrentlig). Korn utenfor 0,001–1000 mm får verdien ved endepunktet; d ≤ 0 gir null.
- **avsetningsfart**(d) → `number | null`: Avsetningsfarten fra Hjulströms diagram: under denne vannfarten (m/s) legger et korn som fraktes seg på bunnen. Alltid lavere enn erosjonsfarten. Log–log-interpolasjon i `HJULSTROM_AVSETNING` (omtrentlig); d ≤ 0 gir null.
- **kornTilstand**(d, v, iBevegelse) → `KornTilstand | null`: Tilstanden til et korn i Hjulströms diagram. Poenget med de to kurvene er at svaret avhenger av om kornet allerede er i bevegelse: – over erosjonskurven rives et korn i ro løs (`'eroderes'`), og et korn i bevegelse fraktes videre; – mellom kurvene blir et korn i ro liggende, mens et korn i bevegelse fraktes videre; – under avsetningskurven legger et korn i bevegelse seg (`'avsettes'`), og et korn i ro blir liggende.
- **synkefart**(d, valg?) → `number | null`: Synkefarten (m/s) til et korn i stillestående vann: Stokes' lov for fine korn (silt og leire synker svært sakte), overgang til √d-lov for grove korn (Ferguson og Church 2004). 0,01 mm silt synker ca. 0,09 mm/s, 1 mm sand ca. 0,13 m/s. d ≤ 0 eller ugyldige valg gir null.
- **transportform**(d, v) → `Transportform | null`: Om et korn som fraktes, holdes svevende eller går langs bunnen. Kornet svever når turbulensen (skjærhastigheten, her forenklet til en tidel av vannfarten, omtrent riktig ved ca. 1 m dyp) er større enn synkefarten (Bagnolds kriterium, forenklet). Leire og silt svever nesten alltid, grus og stein går langs bunnen. Ugyldige tall gir null.
- **kumulativKurve**(sikter, masser, bunn?) → `KurvePunkt[] | null`: Kumulativ kornfordelingskurve fra en sikteanalyse: prosent gjennomgang for hver sikt, sortert fra fineste til groveste sikt. Gjennomgangen ved en sikt er alt som ligger på de finere siktene og i bunnpannen, delt på total masse. Kurven når 100 % ved den groveste sikten bare når ingenting ble liggende på den. Ugyldige data (ulik lengde, sikt ≤ 0, samme sikt to ganger, negativ masse eller total masse 0) gir null.
- **lognormalKurve**(d50, sortering, d?) → `KurvePunkt[] | null`: En kornfordeling som er normalfordelt på φ-skalaen (lognormal i mm), slik mange naturlige sedimenter er: `d50` er mediankornet og `sortering` standardavviket σ i φ-enheter (0,3 = svært godt sortert strandsand, 1 = moderat sortert, 2–3 = morene). Gir punkter jevnt fordelt i φ fra φ50 − 4σ til φ50 + 4σ, eller ved diametrene i `d` (f.eks. en siktesats). Ugyldig d50 eller sortering ≤ 0 gir null.
- **dPersentil**(kurve, p) → `number | null`: Kornstørrelsen (mm) der kurven krysser `p` % gjennomgang: d10, d30, d50, d60 … Interpolerer lineært i log d mellom siktene, som når kurven tegnes på logaritmisk akse. Gir null når kurven ikke når p (f.eks. d10 når mer enn 10 % går gjennom den fineste sikten: da kan d10 ikke bestemmes uten slemmeanalyse).
- **gjennomgangVed**(kurve, d) → `number | null`: Gjennomgangen (prosent finere) ved diameteren `d`, lest av kurven med interpolasjon i log d. Under den fineste sikten er svaret bare kjent når kurven er 0 der, over den groveste bare når kurven er 100 der; ellers null.
- **graderingstall**(kurve) → `number | null`: Graderingstallet Cu = d60/d10: hvor mange kornstørrelser massen spenner over. Nær 1 er ensgradert (alle korn like store, godt sortert), over 15 er velgradert (mange størrelser, typisk morene). Null når d10 eller d60 ikke kan leses av.
- **krumningstall**(kurve) → `number | null`: Krumningstallet Cc = d30² / (d10 · d60), som sier noe om formen på kurven (1–3 for en jevn, velgradert masse). Null når en av persentilene ikke kan leses av.
- **gradering**(cu) → `Gradering | null`: Graderingen for et graderingstall Cu: `'ensgradert'` under 6, `'mellomgradert'` 6–15 og `'velgradert'` over 15 (geoteknikk; velgradert betyr dårlig sortert). Ugyldig Cu (under 1) gir null.
- **SORTERINGSKLASSER** (`readonly Sorteringsklasse[]`): Sorteringsklassene etter Folk og Ward 1957 (σ i φ-enheter).
- **sortering**(kurve) → `Sortering | null`: Sorteringen av en kornfordeling etter Folk og Ward 1957: det inklusive grafiske standardavviket σI i φ-enheter og klassenavnet («godt sortert», «dårlig sortert» …). Godt sortert tyder på vann eller vind (strandsand, breelvsand), svært dårlig sortert på morene. Sorteringen er uavhengig av middelkornstørrelsen. φn er størrelsen der n % av massen er grovere, altså d med (100 − n) % gjennomgang. Null når 16- eller 84-persentilen ikke kan leses av.
- **sorteringsklasse**(sigma) → `Sorteringsklasse | null`: Sorteringsklassen for et standardavvik σ i φ-enheter (Folk og Ward 1957). Negativ eller ugyldig σ gir null.
- **fraksjonsandeler**(kurve) → `Fraksjonsandeler | null`: Hvor mange prosent av massen som er leire, silt, sand, grus, stein og blokk, lest av kurven ved klassegrensene. Klasser som kurven ikke dekker, blir null: en sikteanalyse som slutter ved 0,063 mm gir finstoffet, men ikke fordelingen på silt og leire.
- **klassifiserLosmasse**(kurve) → `LosmasseNavn | null`: Et enkelt navn på en løsmasse fra kornfordelingen, forenklet etter norsk praksis (NGF melding 2): hovedordet er fraksjonen med mest masse, og fraksjoner med minst 20 % (leire fra 10 %) blir tilleggsord, den største nærmest hovedordet («siltig sandig grus»). Når silt og leire ikke kan skilles (sikteanalyse uten slemmeanalyse), kalles de «finstoff», og navnet får en merknad. Null når kurven ikke gir noen andeler.
- Typer: `KornklasseId = 'leire' | 'silt' | 'sand' | 'grus' | 'stein' | 'blokk'`, `Kornklasse { id, navn, adjektiv, min, max }`, `KornTilstand = 'ligger' | 'eroderes' | 'transporteres' | 'avsettes'`, `SynkefartValg { tetthet?, vanntetthet?, viskositet? }`, `Transportform = 'svevende' | 'langs-bunnen'`, `KurvePunkt { d, gjennomgang }`, `Gradering = 'ensgradert' | 'mellomgradert' | 'velgradert'`, `SorteringsklasseId = 'svaert-godt' | 'godt' | 'moderat-godt' | 'moderat' | 'darlig' | 'svaert-darlig' | …`, `Sorteringsklasse { id, navn, min, max }`, `Sortering { sigma, klasse, navn, middelPhi, middelD, metode }`, `Fraksjon = KornklasseId | 'finstoff'`, `Fraksjonsandeler { klasser, finstoff }`, `LosmasseNavn { navn, hoved, tillegg, merknad }`

## hydrologi.ts

- **oppholdstid**(volum, strom) → `number | null`: Oppholdstiden i et magasin: volum delt på strømmen gjennom det (inn eller ut, som er like store i likevekt). Med volum i km³ og strøm i km³ per år blir svaret i år. Strøm ≤ 0 gir null (vannet blir der for alltid); volum 0 gir 0.

- **vannbalanse**(inn) → `Vannbalanse | null`: Vannbalanselikningen for et nedbørfelt: P = E + Q + ΔS, løst for avrenningen Q. Ugyldige tall eller negativ nedbør eller fordampning gir null.

- **avrenningFraVannforing**(q, arealKm2) → `number | null`: Avrenningen i mm per år for en middelvannføring `q` (m³/s) fra et felt på `arealKm2` km². Areal ≤ 0 gir null.

- **darcy**(K, gradient) → `number | null`: Darcys lov: Darcy-hastigheten (spesifikk vannføring) q = K · i i m/s, altså vannmengden per areal av hele tverrsnittet (korn og porer). Vannet i porene går fortere, se `porefart`. Negativ gradient gir strøm motsatt vei. K < 0 eller ugyldige tall gir null.
- **porefart**(q, effektivPorositet) → `number | null`: Porefarten v = q/nₑ (m/s): hvor fort vannet (og en forurensning) faktisk beveger seg gjennom porene. Alltid større enn Darcy-hastigheten, fordi vannet bare går gjennom porene. Effektiv porøsitet ≤ 0 eller over 1 gir null.
- **reisetid**(avstand, fart) → `number | null`: Reisetiden t = L/v for vann (eller en forurensning som følger vannet) over avstanden L med farten v, i samme tidsenhet som farten (m/s gir sekunder; del på `SEK_PER_DOGN` for døgn). L = 0 gir 0; v ≤ 0 gir null (vannet kommer aldri fram).

- **transmissivitet**(K, tykkelse) → `number | null`: Transmissiviteten T = K · b (m²/s): hvor lett vann strømmer gjennom hele tykkelsen b av det vannførende laget. Negative eller ugyldige tall gir null.
- **senkning**(r, Q, T, R, rBronn?) → `number | null`: Senkningen (m) av grunnvannsspeilet i avstanden r fra en brønn som pumper Q (Thiem, forenklet): s = Q/(2πT) · ln(R/r). Senkningen er 0 ved påvirkningsradien R og utenfor, og størst ved brønnen (r regnes som minst brønnradien). Tette masser (liten T) gir en dyp, smal trakt; grus gir en grunn, vid trakt (se `paavirkningsradius`). Negativ r regnes som avstand, så du kan sende inn x − xBrønn. Ugyldige tall, T ≤ 0 eller R ≤ brønnradien gir null.
- **paavirkningsradius**(T, S, t) → `number | null`: Påvirkningsradien (m) rundt en brønn etter pumpetiden t (Cooper og Jacob 1946): R = 1,5 · √(T t / S). Den vokser med tiden og med transmissiviteten, så trakten blir vid i grus. Ugyldige tall eller S ≤ 0 gir null.

- **plotteposisjon**(rang, n, metode?) → `Plotteposisjon | null`: Plotteposisjonen for den m-te største verdien i en serie på n år: overskridelsessannsynlighet og gjentaksintervall. Med Weibull er T = (n + 1)/m, så den største flommen i en 60-årsserie plottes ved 61 år. Rang utenfor 1–n gir null.

- **gumbelTilpasning**(serie) → `Gumbel | null`: Tilpasser en Gumbel-fordeling til en serie med årsmaksima med momentmetoden (α = √6 · s/π, u = x̄ − 0,5772 · α). Krever minst to år; ellers null.
- **flomMedGjentaksintervall**(gumbel, T) → `number | null`: Flommen (samme enhet som serien) med gjentaksintervall T år etter en Gumbel-fordeling: x_T = u − α · ln(−ln(1 − 1/T)). Øker med T. T ≤ 1 gir null (ikke Infinity).
- **gjentaksintervall**(gumbel, verdi) → `number | null`: Gjentaksintervallet (år) for en flom på `verdi` etter en Gumbel-fordeling: T = 1/(1 − F(verdi)). Brukes til å vise at dagens 200-årsflom blir vanligere med klimapåslag. Null når T ikke er endelig (verdien er så stor at den praktisk talt aldri overskrides, eller α = 0).

- **medKlimapaslag**(q, prosent) → `number | null`: Flomvannføringen med klimapåslag: Q · (1 + prosent/100). Ugyldige tall gir null.

  - Props: `at?: readonly [number, number]`, `temperatur: readonly number[]`, `nedbor: readonly number[]`, `width = 800`, `height?`, `temperaturOmrade?: readonly [number, number]`, `nedborMaks?`, `nullLinje = false`, `farget = false`, `markert?`, `maaneder: readonly string[] = KLIMA_MAANEDER`, `sted?`, `visSnitt = false`, `children?: (s: LogPlotSkalaer) => ReactNode`

- **GeoTidslinje**: Tidslinje for geologisk tid: periodebånd i ICS-fargene fra `GEOLOGISK_TID` (eoner, eraer, perioder og epoker), tidsakse i millioner år, tusen år eller år, lineær eller logaritmisk, og hendelsesmerker med tekst. Vannrett (eldst til venstre) eller loddrett (eldst nederst, som ICS-kartet). `fra` og `til` zoomer inn, og navnene i båndene velges etter plassen (fullt navn, kort navn eller ingenting). Hendelsene står som flagg over båndene uten at streker og tekster krysser hverandre (`flaggEtiketter`); når det blir for trangt, blir de nummererte merker med en liste over. Boksen er (x, y, width, height); tidsaksen går over hele bredden (vannrett) eller høyden (loddrett), så la det være litt luft rundt for tallene i endene. Mange hendelser på smal skjerm: bruk `retning="loddrett"` eller mer høyde. `<GeoTidslinje x={20} y={10} width={760} height={260} hendelser={GEO_HENDELSER} markor={alder} markert={periodeVed(alder)?.id} /> <GeoTidslinje … retning="loddrett" fra={66} niva={['periode', 'epoke']} />` `tidslinjeGeometri` gir den samme plasseringen utenfor komponenten.

## kotekart.tsx
Kart for geofag: `Kotekart` tegner et høydefelt fra kart.ts som et topografisk kart (høydelag, relieffskygge, koter med kotetall, hav, innsjøer, elver, vannskille, soner, merker, profillinje, nordpil og målestokk), og `Profildiagram` tegner terrengprofilet langs en linje med valgfri overhøyde. Hjelpere: `kartSkala` (meter → figur), `ekvidistanseFor`, `hoydelagFor` (til en tegnforklaring), `glattSti` (glatt kurve gjennom punkter) og `jevnLinje` (fjerner trappetrinn).

- **glattSti**(punkter, lukket?) → `string`: Glatt SVG-sti gjennom punktene (Catmull-Rom gjort om til kubiske Bézier-kurver), åpen eller lukket. Punktene er i figurens enheter. Brukes til koter, kystlinjer, elver og soner, så knekkene fra rutenettet forsvinner. Like punkter etter hverandre hoppes over; under to punkter gir tom sti.
- **jevnLinje**(punkter, lukket?, runder?) → `[number, number][]`: Jevner ut en linje med glidende middel (vektene 1, 2, 1), `runder` ganger, så trappetrinnene fra et rutenett (elver fra `flytvei`, vannskiller) blir myke kurver. Endepunktene i en åpen linje ligger fast; en lukket linje jevnes rundt. Ugyldige punkter fjernes.
- **kartSkala**(felt, width, x?, y?) → `KartSkala`: Skalaen fra terrenget (meter) til figuren for et kart som er `width` bredt med øvre venstre hjørne i (x, y). Høyden følger av feltet: `h = width · lengde / bredde`.
- **ekvidistanseFor**(felt, maksKoter?) → `number`: En passende ekvidistanse (m) for et høydefelt: den minste av 1, 2, 5, 10, 20, 25, 50, 100 … som gir høyst `maksKoter` koter (standard 22). Et flatt felt gir 1.
- **hoydelagFor**(felt, ekvidistanse?, hav?, grenser?) → `Hoydelag[]`: Høydelagene `Kotekart` bruker, fra lavest til høyest (til en tegnforklaring med `Legend`). Standard: grensene følger kotene (et multiplum av ekvidistansen), høyst seks lag, og fargene spres fra lavland (grønn) til høyfjell (lys grå). Med egne grenser (m o.h.) får laget over grense nr. i fargen `GEO.hoydelag[i + 1]` (fast betydning). Med `hav` begynner det laveste laget ved havnivå.
- **Kotekart**: Topografisk kart fra et høydefelt (`hoydefelt` i kart.ts): høydelag i farger, myk relieffskygge med lys fra nordvest, koter med hver femte tykk og med tall (lesbare, eller med toppen mot høyere terreng som på norske kart), hav med kystlinje, innsjøer, elver som følger terrenget (`flytvei`), vannskille og nedbørfelt (`vannskille`), soner (faresoner, arealbruk), merker (topper med høyde, hus, brønner), profillinje A–B, nordpil og målestokk med ekvidistanse. Øvre venstre hjørne er (x, y), og høyden er `width · lengde / bredde`. Tekst og symboler vokser på mobil; kotetallene holder seg unna navn, merker, nordpila og målestokken, og elvenavnene står der elva ikke deler løp med en annen elv: `` const felt = useMemo(() => hoydefelt(7, former, { bredde: 2000, lengde: 1400, gulv: 0 })!, []); <Figure viewBox={`0 0 800 ${800 * felt.lengde / felt.bredde}`} label="Kotekart"> <Kotekart felt={felt} width={800} hav={0} elver={[{ fra: [1500, 200] }]} profil={{ A: [200, 700], B: [1800, 700] }} /> </Figure> ``
  - Props: `x?`, `y?`, `felt: Hoydefelt`, `width`, `ekvidistanse?`, `hovedkoteHver?`, `kotetall?`, `kotetallRetning?: 'lesbar' | 'terreng'`, `hoydelag?: boolean | readonly number[]`, `relieff?`, `hav?`, `innsjoer?: readonly KartInnsjo[]`, `elver?: readonly KartElv[]`, `vannskiller?: readonly KartVannskille[]`, `soner?: readonly KartSone[]`, `merker?: readonly KartMerke[]`, `profil?: KartProfil`, `nordpil?`, `maalestokk?: boolean | number`, `visEkvidistanse?`, `dempet?`, `children?: (s: KartSkala) => ReactNode`
- **Profildiagram**: Terrengprofilet langs linja A–B i et høydefelt (`terrengprofil` i kart.ts): avstand langs bakken (m eller km) mot høyde (m o.h.), med terrenget fylt og havet som vann. Med `overhoyde` blir høydeaksen strukket nøyaktig så mange ganger i forhold til avstandsaksen (1 = riktige forhold), og overhøyden skrives øverst, så eleven ser hvor mye profilet overdriver. Øvre venstre hjørne er `at` (standard [0, 0]). Bygd på `LogPlot` med lineære akser; barna får skalaene (`sx` i meter langs profilet, `sy` i m o.h.).
  - Props: `at?: readonly [number, number]`, `felt: Hoydefelt`, `A: Kartpunkt`, `B: Kartpunkt`, `width = 800`, `height?`, `overhoyde = null`, `navn: readonly [string, string] = ['A', 'B']`, `hav = null`, `visOverhoyde = true`, `children?: (s: LogPlotSkalaer) => ReactNode`
- Typer: `KartSkala { px, py, punkt, k, x0, y0, w, h, mx, my }`, `Hoydelag { fra, til, farge }`, `KartInnsjo { punkt, niva, navn? }`, `KartElv { fra?, punkter?, navn?, bredde? }`, `KartVannskille { utlop, fyll?, utlopMerke?, navn?, farge? }`, `KartSone { punkter?, verdi?, farge, navn?, skravur?, fyll?, kant?, etikett? }`, `KartMerke { p, symbol?, navn?, hoyde?, farge? }`, `KartProfil { A, B, navn?, farge? }`, `KotekartProps`, `ProfildiagramProps`

## snitt.tsx
Snitt gjennom berggrunnen, i tre former:
- `Snittblokk`: blokkdiagram med overflaten oppå i svakt perspektiv (terreng, vann, hav, fjord eller isdekke), snittet foran og lagene videre på sideflaten. Lagene gis som funksjoner av x eller polygoner, og forkastninger og erosjonsflater (diskordanser) virker på lagene i riktig rekkefølge, som i relativ datering.
- `Lagpakke`: lagrekke med eldste lag nederst, pil «yngre», dybdeakse og etiketter i egen kolonne (under figuren på smal skjerm).
- `Borekjerne`: stående sylinder med lys og skygge, lagene fra en Lagpakke-liste, valgfrie varv og prøvemerker.

- **snittFordelEtiketter**(onsket, hoyder, min, max) → `number[]`: Plasserer etiketter langs en akse uten at de overlapper: hver etikett vil stå med midten i `onsket[i]` og er `hoyder[i]` høy. Gir midtpunktene i samme rekkefølge, innenfor [min, max] så langt det går. Ugyldige tall behandles som min.
- **SnittEtiketter**: Etiketter i en egen kolonne ved siden av et snitt, med tynne streker til det de peker på, som i lærebøkene. Etikettene flyttes så de ikke overlapper (også når teksten vokser på mobil). Ankerpunktet er (x, y) i hver etikett; kolonnen står ved `x` i propsene. `<SnittEtiketter x={640} topp={20} bunn={300} etiketter={[{ x: 500, y: 120, tekst: 'Sandstein' }]} />`
  - Props: `x`, `etiketter: readonly SnittEtikett[]`, `topp`, `bunn`, `anchor: 'start' | 'end' = 'start'`, `size = 0.8`, `prikk = true`
- **snittGeologi**(lag, forkastninger?, h?) → `SnittGeologi`: Geologien i en Snittblokk som rene funksjoner: hvilket lag som er i et punkt etter at alle lag, erosjonsflater og forkastninger er tatt med i riktig rekkefølge. Lagene gis med det eldste først (som i `Snittblokk`), og `h` er bunnen av snittet. Nyttig i kapitlene, f.eks. «hvilket lag treffer borehullet på 120 m dyp?». `const geo = snittGeologi(lag, [{ x: 300, sprang: 40 }], 300); geo.lagVed(400, 150)   // indeksen i lag, eller −1`
- **lagflate**(y0, valg?) → `(x: number) => number`: En lagflate som funksjon av x til `topp` og `bunn` i SnittLag: vannrett i høyden `y0`, skrå (`fall`), foldet (`amplitude`, `bolgelengde`) eller med en kuppel. Gi alle lagene samme valg og ulik `y0`, så blir de parallelle. `const fold = { amplitude: 40, bolgelengde: 520, midt: 300 }; lag = [{ type: 'sandstein', topp: lagflate(200, fold) }, { type: 'leirskifer', topp: lagflate(150, fold) }]`
- **snittblokkPerspektiv**(dybde?, vinkel?) → `{ dx: number; dy: number }`: Perspektivet i en Snittblokk: hvor langt bakkanten er forskjøvet (dx mot høyre, dy oppover) for en blokk.
- **useSnittblokk**() → `SnittblokkInfo | null`: Informasjon om Snittblokka et barn er tegnet i (mønster-id, mål, overflate og geologi), eller null utenfor en Snittblokk.
- **Snittblokk**: Blokkdiagram av berggrunnen: snittet foran, overflaten oppå i svakt perspektiv (gress, jord, fjell, snø eller et geologisk kart, med vann, hav, fjord eller isdekke) og lagene videre på sideflaten til høyre, med lys ovenfra og myk skygge. Lagene gis med det eldste først, som bånd (`topp`, `bunn`) eller polygoner; forkastninger og erosjonsflater virker på lagene som var dannet da, så figuren følger prinsippene for relativ datering. Ankerpunkt: (x, y) er øverste venstre hjørne av snittet foran. Et punkt (sx, sy) i snittet står i (x + sx, y + sy) i figuren; bakkanten er forskjøvet (dx, −dy) fra `snittblokkPerspektiv(dybde, vinkel)`. Barna tegnes i snittets koordinater og klippes til berggrunnen (bruk `useSnittblokk()` for mønster-id og overflate), `over` tegnes oppå uten klipping. Med `etiketter` står lagnavnene i en kolonne til høyre for blokka, fra x + w + dx + 18.
  - Props: `x = 0`, `y = 0`, `w`, `h`, `lag: readonly SnittLag[]`, `forkastninger: readonly SnittForkastning[] = []`, `overflate?: SnittKurve`, `mark: SnittMark | ((x: number, y: number) => SnittMark) = 'gress'`, `vann?: SnittVann | readonly SnittVann[]`, `is?: SnittIs`, `dybde?`, `vinkel?`, `skygge = true`, `etiketter = false`, `dim?`, `children?`, `over?`
- **SnittGang**: Gang (loddrett eller skrå) eller lagergang (vannrett) som skjærer gjennom lagene i en Snittblokk: et bånd med litt ujevne kanter og avkjølt rand (mørkere kant), fylt med bergartsmønsteret eller som smeltet magma. Tegnes som barn av Snittblokk (snittets koordinater, klippes til berggrunnen); utenfor en Snittblokk tegner den sine egne mønstre. `<SnittGang fra={[180, 300]} til={[230, 0]} bredde={14} />      // gang til overflaten <SnittGang fra={[60, 160]} til={[420, 150]} type="gabbro" />   // lagergang`
  - Props: `fra: SnittPunkt`, `til: SnittPunkt`, `bredde = 12`, `type: MonsterId = 'diabas'`, `smelte?`, `seed = 3`, `dim?`
- **SnittMagmakammer**: Magmakammer i en Snittblokk: en ujevn, glødende linse (varmest i midten) med tilførselskanal nedenfra og valgfri kanal opp til overflaten, eller en størknet pluton med bergartsmønster (`stivnet`). Ingen filtre: gløden er en radiell toning. Ankerpunkt: (x, y) er midten av kammeret, i snittets koordinater. `<SnittMagmakammer x={300} y={230} rx={90} ry={34} kanal={330} /> <SnittMagmakammer x={300} y={230} rx={90} ry={40} stivnet="granitt" tilforsel={false} />`
  - Props: `x`, `y`, `rx`, `ry`, `tilforsel = true`, `kanal?`, `stivnet?: boolean | MonsterId`, `seed = 5`, `dim?`
- **lagpakkeDybder**(lag) → `{ intervaller: LagpakkeIntervall[]; total: number }`: Dybden til toppen og bunnen av hvert lag, regnet fra toppen av pakka (det yngste laget har toppen i 0). Gir lagene ovenfra og ned (yngste først) og den samlede tykkelsen. Lag med tykkelse 0 eller ugyldig tykkelse er med i rekkefølgen, men ikke i lista.
- **lagpakkeOppsett**(v, fInn?) → `LagpakkeOppsett`: Oppsettet til en Lagpakke for tekstskaleringen `f` (fra `useContainerTextScale`): hvor kolonnen, aksen og etikettene står, og hvor høy komponenten blir. Etikettene står til høyre når de får plass (`etiketter: 'auto'`), ellers i en forklaring under kolonnen med nøkler (1, 2, 3 … ovenfra). Bruk `hoyde` til viewBox-en: `` const opp = lagpakkeOppsett({ bredde: 360, hoyde: 260, lag }, f); <Figure viewBox={`0 0 400 ${opp.hoyde + 20}`}>…<Lagpakke x={20} y={10} bredde={360} hoyde={260} lag={lag} /></Figure> ``
- **Lagpakke**: Lagrekke med det eldste laget nederst, som i PDF-malen «Atlas»: en kolonne med mønstrene (lys fra venstre), pil «yngre» lengst til venstre, dybdeakse og etiketter midt for hvert lag i en egen kolonne til høyre. Når etikettene ikke får plass (smal skjerm), står de i en forklaring under kolonnen, med nøkler (1, 2, 3 … ovenfra) ved lagene. Lagene er i målestokk; en erosjonsflate tegnes som en bølget linje. Ankerpunkt: (x, y) er øverste venstre hjørne av området. `lagpakkeOppsett` gir hele høyden til viewBox-en.
  - Props: `x`, `y`, `bredde`, `hoyde`, `lag: readonly LagpakkeLag[]`, `enhet = 'm'`, `akseTittel?`, `kolonne?`, `dybdeakse?`, `yngre?`, `etiketter?: 'auto' | 'hoyre' | 'under' | 'ingen'`, `profil: 'rett' | 'korn' = 'rett'`, `gress?`
- **Borekjerne**: Borekjerne: en stående sylinder med lys fra venstre og myk skygge, lagene fra en Lagpakke-liste (eldste nederst) som bånd rundt kjernen, valgfrie varv (årlige par av lyst sommerlag og mørkt vinterlag), prøvemerker med etikett, brudd og dybdeakse. Ankerpunkt: (x, y) er midten av den øverste endeflaten; kjernen går ned til y + hoyde, og etikettene står fra x + bredde/2 + 22. `<Borekjerne x={120} y={30} bredde={46} hoyde={260} lag={[ { type: 'morene', tykkelse: 2 }, { type: 'leire', tykkelse: 3, varv: 24 }, { type: 'torv', tykkelse: 1 }, ]} prover={[{ dybde: 1.2, navn: 'Prøve A', tekst: '9 800 år' }]} dybdeakse />`
  - Props: `x`, `y`, `bredde`, `hoyde?`, `pxPerEnhet?`, `lag: readonly LagpakkeLag[]`, `prover: readonly BorekjerneProve[] = []`, `etiketter?`, `dybdeakse?`, `enhet = 'm'`, `brudd = 0`, `seed = 2`, `dim?`
- Typer: `SnittPunkt`, `SnittKurve`, `SnittEtikett { x, y, tekst, undertekst?, uthevet?, dim? }`, `SnittEtiketterProps`, `SnittLag { type, topp?, bunn?, punkter?, erosjon?, navn?, undertekst?, dim?, uthevet? }`, `SnittForkastning { x, y?, fall?, heller?, sprang, lag?, piler? }`, `SnittGeologi { lagVed, topp, bunn, polygoner, forkastninger, margin }`, `LagflateValg { fall?, amplitude?, bolgelengde?, midt?, kuppel? }`, `SnittMark = 'gress' | 'jord' | 'fjell' | 'sno' | 'kart'`, `SnittVann { niva, fra?, til?, type? }`, `SnittIs { topp, fra?, til? }`, `SnittblokkProps`, `SnittblokkInfo { monstre, w, h, dx, dy, overflate, geologi }`, `SnittGangProps`, `SnittMagmakammerProps`, `LagpakkeLag { type, tykkelse, navn?, tekst?, kort?, varv?, erosjon?, dim?, uthevet? }`, `LagpakkeIntervall { indeks, topp, bunn, tykkelse }`, `LagpakkeOppsettValg { bredde, hoyde, lag, kolonne?, dybdeakse?, yngre?, etiketter?, profil?, enhet?, akseTittel? }`, `LagpakkeOppsett { plassering, hoyde, kolonneX, kolonneY, kolonneBredde, kolonneHoyde, aksX, pilX, etikettX, forklaring, skala, merker, desimaler }`, `LagpakkeProps`, `BorekjerneProve { dybde, navn?, tekst? }`, `BorekjerneProps`

## tektonikk.tsx
Platetektonikk og vulkaner i illustrert realisme (lys ovenfra, kontur og myke toninger, ingen filtre):
- `JordasIndre`: jordkula med en utskåret kile (eller som et helt snitt), lagene etter radiene i jorda.ts.
- `Plategrense`: blokkdiagram av en plategrense med litosfære, astenosfære, magma, skjelv og bevegelse med tiden: spredning, subduksjon (hav–kontinent og hav–hav), kollisjon og varmt punkt, og transformforkastning som kart ovenfra.
- `Vulkan`: skjoldvulkan eller stratovulkan (også erodert), utvendig eller i snitt med magmakammer, og utbrudd med lavastrøm, lavafontene og askesky.
Rene hjelpere: `MAGNETISK_POLARITET`, `polaritetVed`, `magnetiskeStriper`, `jordasIndreRadius`, `jordasIndreRadier`, `jordasIndreGeometri`, `plategrenseGeometri` og `vulkanGeometri`. Ugyldige tall gir null, aldri NaN eller Infinity.

- **MAGNETISK_POLARITET** (`readonly PolaritetsIntervall[]`): Jordas magnetfelt de siste 6 millioner år: intervaller med normal og omvendt polaritet, yngst først, med kronene (Brunhes, Matuyama, Gauss, Gilbert) og de korte episodene i dem (Jaramillo, Olduvai, Kaena, Mammoth, Cochiti, Nunivak, Sidufjall, Thvera). Grunnlaget for de magnetiske stripene i `Plategrense` og `magnetiskeStriper`.
- **STRIPER_START**: Hvor langt tilbake stripene i `Plategrense` går (millioner år).
- **polaritetVed**(alder) → `boolean | null`: Polariteten for en alder (millioner år): true = normal (som i dag), false = omvendt. En alder på en grense hører til det yngre intervallet. Null for negative og ugyldige aldre og for aldre eldre enn tabellen (6,033 millioner år).
- **magnetiskeStriper**(fart, t, start?) → `MagnetiskStripe[]`: Stripene på den ene siden av en spredningsrygg (de er speilvendt på den andre siden). `fart` er spredningsfarten i cm per år mellom platene (hver side flytter seg med halvparten), `t` hvor mange millioner år som har gått siden figuren startet for `start` millioner år siden (standard 5). Skorpa som ble dannet ved tiden τ etter start, ligger nå (t − τ) · v km fra ryggen og har polariteten fra (start − τ) millioner år før i dag. Ved t = start er mønsteret som på havbunnen i dag; t over start regnes som start. Avstanden ut til den eldste stripa er 5 · fart · t km. Gir [] når fart eller t er 0 eller ugyldig. `magnetiskeStriper(4, 5)[0]   // { fra: 0, til: 15,6, normal: true, navn: 'Brunhes', … }  (20 km per million år)`
- **jordasIndreRadius**(dybde, r, riktigeForhold?) → `number | null`: Den tegnede radien (figurens enheter) for et dyp i km i en jordkule med radius `r`. ## vann.tsx
Vann i geofagfigurene: grunnvann i snitt (`Grunnvannssnitt` med umettet sone, kapillærsone, grunnvannsspeil og mettet sone), brønner i snitt (`Bronn`: borebrønn i fjell, løsmassebrønn, gravd brønn, observasjonsbrønn, energibrønn og borehull), nedbør med skydekke (`Nedbor`, `Skydekke`) og strømmer langs en sti (`Stromlinjer`: grunnvann, isstrøm, mantelstrøm, karbon- og vannstrømmer, bølgefronter).

- **senkningstrakt**(speil, ...bronner) → `(x: number) => number`: Grunnvannsspeil med senkningstrakt rundt én eller flere brønner som pumper: speilet `speil` (tall eller y(x)) senket med s(r) = s₀ · ln(R / r) / ln(R / r_b) for r_b ≤ r ≤ R (Thiems likning for et åpent magasin, forenklet), og summen når traktene overlapper. Gir en funksjon y(x) som kan gis rett til `speil` på Grunnvannssnitt: `speil={senkningstrakt(140, { x: 300, senkning: 40, radius: 220 })}` Brønner med radius ≤ 0 eller ugyldige tall hoppes over, så funksjonen gir aldri NaN.
- **grunnvannGeometri**({ w, h, overflate, speil, kapillar }) → `GrunnvannGeometri`: Geometrien i et Grunnvannssnitt som ren funksjon: bakken, speilet, kapillærsonen og innsjøene der speilet står over bakken (vannflaten er vannrett, i høyden der speilet møter bakken). Bruk den til å sette brønner, hus og piler på riktig sted: `const g = grunnvannGeometri({ w, h, overflate, speil }); <Bronn x={300} y={g.overflate(300)} …/>`. Standard bakke 0,15 · h, speil 0,45 · h og kapillærsone 0,05 · h (6–28). Gir aldri NaN.
- **Grunnvannssnitt**: Grunnvann i snitt, som i læreboka: lagene (sand, grus, morene, fjell …) med mønster, umettet sone (porer med luft), kapillærsone, grunnvannsspeilet (blå linje med ▽) og mettet sone (blå), gress på toppen i svakt perspektiv og innsjø eller elv der speilet står over bakken. Speilet kan være et tall, en skråning eller en senkningstrakt. Ankerpunkt: (x, y) er øverste venstre hjørne av snittet foran, som i Snittblokk. Et punkt (sx, sy) i snittet står i (x + sx, y + sy); bakkanten er forskjøvet (dx, −dy) fra `snittblokkPerspektiv(dybde, vinkel)`. Bruk `grunnvannGeometri` med de samme verdiene for å sette brønner og piler (`over`), og barna for det som skal klippes til bakken.
  - Props: `x = 0`, `y = 0`, `w`, `h`, `overflate?: SnittKurve`, `speil?: SnittKurve`, `kapillar?: number | false`, `lag: readonly GrunnLag[] = STANDARD_LAG`, `mark: 'gress' | 'jord' | 'sno' | 'ingen' = 'gress'`, `overflatevann = true`, `soner = true`, `speilMerke?: number | false`, `etiketter: 'hoyre' | 'inne' | false = false`, `etikettX?`, `dybde?`, `vinkel?`, `skygge = true`, `dim?`, `children?`, `over?`
- **SpeilSymbol**: Symbolet for grunnvannsspeil (▽ med to korte streker under), som på hydrogeologiske snitt. (x, y) er punktet på speilet: trekanten står over, strekene under. Størrelsen følger useGeoScale.
  - Props: `x`, `y`, `k?`, `s?`
- **BRONN_NAVN** (`Readonly<Record<BronnType, string>>`): Norske navn på brønntypene (til knapper og forklaringer).
- **bronnPunkter**(p, k?) → `BronnPunkter`: Punktene på en brønn (samme props som `Bronn`, og `k` = useGeoScale() i figuren): toppen, vannflaten, pumpen, filteret, enden av ledningen og bunnen, til piler og etiketter: `const p = bronnPunkter({ x: 300, y: 120, bunn: 330, vannstand: 180, type: 'fjell' }, k); <ForceArrow x1={p.pumpe.x} … />`
- **Bronn**: Brønn i snitt: borebrønn i fjell (foringsrør gjennom løsmassene og ned i fjellet, åpent hull i fjellet, dykkpumpe på stigerør), løsmassebrønn (foringsrør med filter nederst), gravd brønn (betongringer med lokk, åpen bunn med grus), observasjonsbrønn (smalt plastrør med filter, beskyttelsesrør og eventuelt peilebånd), energibrønn (foringsrør, U-formet kollektorslange med bunnlodd) eller et rent borehull. Vannet i brønnen står i `vannstand`, med ▽. Ankerpunkt: (x, y) er der brønnen møter bakken, midt på; alle andre høyder er y-verdier i samme koordinater (ikke dybder). Brønnen er tegnet bredere enn i virkeligheten, så den synes; bredden vokser med useGeoScale. Tegn den etter bakken og lagene (i `over` på Grunnvannssnitt eller Snittblokk). Bruk `bronnPunkter` for piler.
  - Props: `x`, `y`, `bunn`, `type: BronnType = 'fjell'`, `vannstand?`, `fjell?`, `filter?: readonly [number, number]`, `pumpe?`, `pumpeDybde?`, `tilkobling?: 'venstre' | 'hoyre'`, `tilkoblingLengde?`, `peilebaand?`, `merke = true`, `bredde?`, `seed = 3`, `dim?`
- **Skydekke**: Skydekke for overskyet vær og regnvær: et sammenhengende skylag av tette skyputer i to lag, med lyse topper og mørkere skybase, i grått som blir mørkere med `tetthet`. Med `himmel` legges et grått slør under skyene, så en solskinnshimmel blir overskyet (tegn da Skydekke rett etter Himmel og før landskapet). Himmel i scene-kit-et har bare sol og haugskyer. Bare toninger, ingen filtre. Ankerpunkt: øverste venstre hjørne. Skyene holder seg mellom x og x + w (avrundet i endene), og skybasen ligger ca. i y + 0,8 · h. Uten `toppkant` er toppen rett (skylaget går ut over figuren).
  - Props: `x = 0`, `y = 0`, `w`, `h`, `tetthet = 0.5`, `himmel?`, `toppkant = avrundet`, `avrundet = false`, `seed = 5`, `dim?`
- **Nedbor**: Nedbør: regn (skrå striper i to avstander), snø (runde fnugg som daler og driver) eller sludd, med intensitet, vind og fast frø, så figuren og skjermbildene blir like hver gang. Med `t` faller den (sett `t={clock.t}`). Med `skydekke` tegnes et skylag øverst, og ved kraftig regn et regnslør under det. Fargen har kontrast mot himmelen i begge temaer. Bygd på Regn og Snofall i fysikk/kap02. Ankerpunkt: øverste venstre hjørne av området. Med `bakke` stopper dråpene ved bakken, så området kan gå ned forbi en terrengprofil. Tegn Nedbor etter landskapet.
  - Props: `x = 0`, `y = 0`, `w`, `h`, `type: NedborType = 'regn'`, `intensitet = 0.5`, `vind = 0.2`, `n?`, `t?`, `bakke?: SnittKurve`, `skydekke?: boolean | { tetthet?, hoyde?, utenSkyer?, avrundet? }`, `seed = 7`, `dim?`
- **langsSti**(punkter, andel, valg?) → `{ x: number; y: number; vinkel: number } | null`: Punktet en andel (0–1) langs en sti (glattet som i Stromlinjer), og retningen der i grader (0 = mot høyre, 90 = ned, som i SVG). Til etiketter, symboler og egne piler langs samme sti. Gir null for en sti uten lengde.
- **stiLengde**(punkter, valg?) → `number`: Lengden på stien (glattet som i Stromlinjer), eller 0.
- **stromBredde**(mengde, maks, maksBredde?, minBredde?) → `number`: Tykkelsen på en strøm proporsjonal med mengden: `mengde / maks · maksBredde`, men aldri tynnere enn `minBredde` (så små strømmer synes). - **Stromlinjer**: Strømmer langs en sti: tykke bånd med pilspiss for mengder i et kretsløp (karbon, vann: bredden etter mengden), tynne strømlinjer med piler (grunnvann, isstrøm), stiplede linjer, partikler eller bølgefronter. En lukket sløyfe gir en konveksjonscelle (mantelstrøm). Med `t` beveger pilene, stiplene, partiklene eller frontene seg langs stien med `fart`. Fargen velger kapittelet; alt har glorie i flatefargen, så det synes oppå mønstre og vann. Ankerpunkt: punktene er i figurens koordinater (eller snittets inne i en Snittblokk eller et Grunnvannssnitt). Strømmen går fra det første punktet til det siste.
  - Props: `linjer?: readonly StromLinje[]`, `punkter?: readonly SnittPunkt[]`, `bredde?`, `label?`, `labelPos?`, `labelSide?: 'venstre' | 'hoyre'`, `farge`, `stil: StromStil = 'baand'`, `glatt = true`, `lukket = false`, `pil?`, `t?`, `fart = 40`, `avstand?`, `labelSize = 0.8`, `dim?`

## landskap.tsx
Landskap formet av is og vann, i snitt og ovenfra:
- `Isbre`: «dalbre» (blokk med lengdesnitt gjennom breen: firn, sprekker, likevektslinje, front, endemorene, sidemorene og bresjø), «innlandsis» (isdekke med valgfri isostasi: skorpa trykkes ned) og «havis» (flak som flyter med omtrent 90 % under vann, valgfritt isfjell til sammenligning).
- `Elveleie`: «lengde» (fra fjell til delta, med korn på bunnen), «tverr» (tverrsnitt med vannstand, flomlinjer, flomslette og målepunkter) og «ovenfra» (meandre eller rett kanal). Vannet er klart, grumsete eller en slamstrøm.
- `Fjellside`, `Bekk` og `Demning`: kopiert fra fysikk/kap03/vannkraft-deler.tsx (FjellSnitt, Bekk, Demning) med nye navn og geofagfarger, så hjulstrom og drikkevann kan bruke dem uten å importere på tvers av fagene.

- **kolonneEtiketter**(punkter, kolonneX, topp, bunn, foretrukket?) → `number[]`: Plasserer etiketter i en kolonne til høyre for punktene de peker på (strekene går fra punktet til `kolonneX`). Prøver flere rekkefølger (etter y, etter x og etter skrå linjer gjennom punktene; rekkefølgen avgjør hvem som viker når det er trangt, ellers står etiketten i høyde med punktet) og velger den som gir minst rot: hvert kryss mellom to streker og hver strek tett forbi et annet punkt teller som mye skråning, så noen få litt skrå streker vinner over et kryss, men ikke over en hel vifte av lange skrå streker. Etikettene flyttes så de ikke overlapper og holder seg mellom `topp` og `bunn` (snittFordelEtiketter). Gir midten (y) til hver etikett i samme rekkefølge som `punkter`; ugyldige punkter får NaN-fri plass øverst. `foretrukket` ('x' eller 'y') vinner ved likhet. `const midt = kolonneEtiketter(punkter, x + w + 18, topp, bunn);`
- **VANN_KLARHET_NAVN** (`Readonly<Record<VannKlarhet, string>>`): Navnene på vanntypene til knapper og forklaringer (bokmål, stor forbokstav bare først).
- **Fjellside**: Fjellside i snitt under et terreng: jord, valgfrie løsmasser (morene i en skråning) og fast fjell med lag og sprekker (eller berggrunnen med geofagmønsteret, `berggrunn`), klippet til terrenget. Ankerpunkt: punktene i `terreng` er i figurens koordinater, og snittet går ned til `bunn`; tegnes rett etter scene-kit-ets Terreng, eller med `mark`, som tegner Terreng selv.
  - Props: `terreng: readonly SnittPunkt[]`, `topp?`, `bunn`, `k = 1`, `seed = 7`, `mark?: 'gress' | 'sno' | 'jord' | 'grus'`, `berggrunn?: MonsterId`, `losmasse?: { type: MonsterId; tykkelse: number }`, `dim?`
- **Bekk**: Bekk i snitt: et tynt lag vann oppå bekkeleiet med lys overflate, krusninger som renner nedover (med `t`) og runde steiner; klart, grumsete eller slamstrøm. Ankerpunkt: punktene i `leie` er i figurens koordinater, fra der bekken starter til der den ender. Tegnes etter terrenget og Fjellside. `<Bekk leie={[[40, 120], [180, 170], [300, 200]]} t={clock.t} />`
  - Props: `leie: readonly SnittPunkt[]`, `t = 0`, `k = 1`, `dybde = 4`, `klarhet: VannKlarhet = 'klar'`, `seed = 3`, `dim?`
- **demningMaal**({ x, y, hoyde, krone, helning, flip }) → `DemningMaal | null`: Målene på en demning (samme geometri som `Demning` tegner): kronen, foten nedstrøms og omrisset. Gir null for ugyldige tall eller høyde ≤ 0.
- **Demning**: Betongdemning i snitt: loddrett side mot magasinet, skrå side nedstrøms, rekkverk på kronen og støpeskjøter; uten `rekkverk` en lav terskel. Ankerpunkt: (x, y) er foten av den loddrette siden mot magasinet (`flip` snur den); `demningMaal` gir kronen og foten nedstrøms. Tegnes etter vannet i magasinet. `<Demning x={420} y={260} hoyde={70} />`
  - Props: `x`, `y`, `hoyde`, `krone?`, `helning?`, `flip?`, `rekkverk = true`, `dim?`
- **ISBRE_NAVN** (`Readonly<Record<IsbreType, string>>`): Navnene på istypene til knapper og forklaringer.
- **DALBRE_STANDARD**: Standardverdiene for en dalbre.
- **likevektsFront**(likevektslinje, valg?) → `number | null`: Hvor langt ned i dalen fronten til en dalbre står i likevekt med en gitt likevektslinje (m o.h.), etter regelen om at omtrent 60 % av breen ligger over likevektslinja (AAR ≈ 0,6). Gir fronten som andel 0–1 av snittet i `Isbre` (samme dal og samme høyder), 1 når breen fyller hele dalen, og null når likevektslinja ligger så høyt at det ikke blir noen bre. Tommelfingerregelen er omtrentlig; den forteller hvilken vei fronten flytter seg, ikke hvor fort. `const front = likevektsFront(ela) ?? 0;   <Isbre likevektslinje={ela} front={front} />`
- **isbreGeometri**(p, f?) → `IsbreGeometri | null`: Geometrien til en `Isbre` i figurens koordinater: rammen rundt alt som tegnes (til viewBox), høyder og andeler som x og y, bakken, istoppen og overflaten ved x, likevektslinja og akkumulasjonsandelen (dalbre), nedsynkingen og kysten (innlandsis) og ankerpunkter til etiketter og piler. `f` er tekstskaleringen (som `useTextScale`); den samme geometrien får barna i `<Isbre>`. Gir null for ugyldige mål. `const g = isbreGeometri({ type: 'dalbre', x: 20, y: 90, w: 600, h: 260, likevektslinje: ela, front }, f);`
- **Isbre**: Is i landskapet som blokkdiagram i Snittblokk-stil: en dalbre i lengdesnitt (firn, sprekker, likevektslinje, front, morener og bresjø), en innlandsis (med valgfri isostasi) eller havis (flak og isfjell). Ankerpunkt: (x, y) er øverste venstre hjørne av snittet foran; blokka stikker dx til høyre og dy opp (fjellsiden bak en dalbre enda høyere), og `isbreGeometri(props, f).ramme` gir hele rammen til viewBox. Havis: y er havflaten.
  - Props: `x?`, `y?`, `type?: IsbreType`, `w`, `h`, `dybde?`, `vinkel?`, `tykkelse?`, `hoyder?: { topp: number; bunn: number }`, `likevektslinje?`, `front?`, `endemorene?: boolean | number | readonly number[]`, `sidemorene?`, `bresjo?`, `sprekker?`, `firn?`, `breelv?`, `soner?`, `fjellvegg?`, `maksTykkelse?`, `senter?`, `utbredelse?`, `isostasi?`, `nedsynking?: number | 'likevekt'`, `havniva?`, `hav?`, `dekning?`, `isfjell?: boolean | number`, `smeltedammer?`, `berggrunn?: MonsterId`, `strom?`, `t?`, `seed?`, `etiketter?`, `skygge?`, `dim?`, `children?: (g: IsbreGeometri) => ReactNode`
- **ELVELEIE_NAVN** (`Readonly<Record<ElveleieVisning, string>>`): Navnene på visningene til knapper.
- **TVERRPROFIL_STANDARD** (`Tverrprofil`): Standardprofilet i `Elveleie visning="tverr"`: 130 m bredt, med flomslette til venstre (en lav voll ved løpet), elveløpet med det dypeste punktet nær 62 m og en terrasse til høyre. Høyder i m over det dypeste punktet.
- **tverrsnittAreal**(profil, niva) → `number | null`: Tverrsnittsarealet av vannet (m²) i et elveprofil ved en vannstand (m o.h.): bare den delen som henger sammen med det dypeste punktet. Null når vannstanden ligger under bunnen eller tallene er ugyldige. `tverrsnittAreal(TVERRPROFIL_STANDARD, 3) // m²`
- **tverrsnittBredde**(profil, niva) → `number | null`: Bredden på vannflaten (m) i et elveprofil ved en vannstand. Null når vannstanden ligger under bunnen.
- **tverrsnittPaneler**(profil, niva, malepunkter) → `{ deler, areal, vannforing } | null`: Deler tverrsnittet i paneler rundt målevertikalene (midtseksjonsmetoden): hver vertikal står for vannet fra midt mellom forrige vertikal til midt mellom neste, og de ytterste panelene går ut til breddene. Vannføringen er summen av fart · areal. Vertikaler utenfor vannet hoppes over. Gir null når vannstanden er under bunnen eller ingen vertikal står i vannet; `vannforing` er null når en av vertikalene mangler fart. `const q = tverrsnittPaneler(profil, 3.2, [{ x: 52, fart: 0.6 }, { x: 62, fart: 1.1 }, { x: 70, fart: 0.7 }]);`
- **elveleieGeometri**(p, f?) → `ElveleieGeometri | null`: Geometrien til et `Elveleie` i figurens koordinater: rammen rundt alt som tegnes (til viewBox), x for en andel langs elva (lengde), en avstand i m (tverr) eller en andel av kartet (ovenfra), bunnen og vannflaten ved x, overhøyden i tverrsnittet, midtlinja ovenfra og ankerpunkter til etiketter og piler. `f` er tekstskaleringen; barna i `<Elveleie>` får den samme geometrien. Gir null for ugyldige mål.
- **Elveleie**: En elv i tre visninger: lengdeprofil fra fjell til delta ('lengde'), tverrsnitt med vannstand, flomlinjer og målevertikaler ('tverr') eller kart ovenfra med meandre eller rett kanal ('ovenfra'); vannet er klart, grumsete eller en slamstrøm. Ankerpunkt: (x, y) er øverste venstre hjørne av snittet foran (lengde og tverr, som i Snittblokk; blokka stikker dx til høyre og dy opp) eller av kartet (ovenfra); `elveleieGeometri(props, f).ramme` gir rammen til viewBox.
  - Props: `x?`, `y?`, `visning?: ElveleieVisning`, `w`, `h`, `dybde?`, `vinkel?`, `klarhet?: VannKlarhet`, `t?`, `seed?`, `etiketter?`, `skygge?`, `dim?`, `children?: (g: ElveleieGeometri) => ReactNode`, `vannforing?`, `korn?`, `munning?`, `soner?: boolean | 'prosess' | 'lop'`, `demning?: { u: number; hoyde?: number }`, `fjellvegg?`, `berggrunn?: MonsterId`, `profil?: Tverrprofil`, `vannstand?`, `flomlinjer?: readonly Flomlinje[]`, `malepunkter?: readonly Malepunkt[]`, `paneler?`, `forbygning?: readonly Forbygning[]`, `akser?`, `overhoyde?`, `form?: 'meandre' | 'rett'`, `slyngning?`, `svinger?`, `kroksjo?`, `bredde?`, `strom?`, `prosesser?`
- Typer: `KolonnePunkt { x, y, hoyde, strek? }`, `VannKlarhet = 'klar' | 'grumsete' | 'slamstrom'`, `FjellsideProps`, `BekkProps`, `DemningProps`, `DemningMaal { krone, fot, vegg, omriss }`, `IsbreType = 'dalbre' | 'innlandsis' | 'havis'`, `IsbreAnkerNavn = 'firn' | 'breis' | 'likevektslinje' | 'sprekker' | 'randkloft' | 'sidemorene' | …`, `IsbreProps`, `IsbreGeometri`, `ElveleieVisning = 'lengde' | 'tverr' | 'ovenfra'`, `Tverrprofil`, `Flomlinje { niva, navn?, farge? }`, `Malepunkt { x, fart?, navn? }`, `Forbygning { x, hoyde, bredde? }`, `TverrsnittDel { x, navn?, fra, til, dybde, areal, fart, vannforing }`, `ElveleieAnkerNavn = 'stein' | 'grus' | 'sand' | 'elveavsetning' | 'delta' | 'leire' | 'berggrunn' | …`, `ElveleieProps`, `ElveleieGeometri`

## korn.tsx
Korn og kornstørrelse i geofagfigurene: ett korn med rundhet og bergartsfarge (`Korn`), et forstørret utsnitt av pakkede korn der porene er fylt med vann, olje, gass, CO₂, luft, sement eller leire (`Kornpakning`), og kumulativ kornfordeling på logaritmisk akse med kornklassene som bånd (`Kornkurve`).

- **RUNDHETSKLASSER** (`readonly Rundhetsklasse[]`): Rundhetsklassene etter Powers 1953, fra svært kantet til godt rundet.
- **rundhetVerdi**(r) → `number`: Rundheten (0–1) for en klasse eller et tall. Ugyldige tall gir 0,6 (noe rundet).
- **rundhetsklasse**(r) → `Rundhetsklasse | null`: Klassen som ligger nærmest rundheten `r` (0–1). Ugyldige tall gir null.
- **kornOmriss**(valg?) → `KornOmriss`: Omrisset av et korn med radius 1 rundt (0, 0): et tilfeldig (men fast for frøet) mangekantet korn der hjørnene rundes av etter rundheten, fra skarpe kanter (svært kantet, f.eks. forvitret grus og morene) til en jevn, rund form (godt rundet, f.eks. strandsand og elvestein). Ingen del av kornet ligger lenger enn 1 fra midten, så korn med radius r kan pakkes som sirkler. Ren funksjon.
- **kornSti**(x, y, r, omriss?, rotate?) → `string`: SVG-stien til et korn med midten i (x, y) og radius r, dreid `rotate` grader: de avrundede hjørnene som kvadratiske buer (skarpe ved rundhet 0). Gi enten et ferdig omriss eller valgene til `kornOmriss`. `<path d={kornSti(120, 80, 14, { rundhet: 0.2, seed: 4 })} … />`
- **kornRamme**(valg?) → `{ venstre, hoyre, topp, bunn }`: Hvor langt et korn med radius 1 rekker ut fra midten til hver side, etter dreiingen: `{ venstre, hoyre, topp, bunn }` (venstre og topp er negative, y nedover). Gang med radiusen (d/2, og `useGeoScale` når kornet vokser på mobil) for å sette en etikett rett over et korn som ligger på bunnen (`anker="bunn"`): toppen er y − (bunn − topp) · r. Ren funksjon.
- **punktIPolygon**(x, y, poly) → `boolean`: Om punktet (x, y) ligger inne i polygonet (jevn–odde-regelen).
- **polygonAreal**(poly) → `number`: Arealet av et polygon (alltid positivt).
- **voronoiMosaikk**(punkter, boks, naboAvstand?) → `VoronoiMosaikk`: Voronoi-mosaikken til punktene innenfor boksen, med naboene: hver celle er området som ligger nærmere sitt punkt enn noe annet, og for hver kant vet vi hvilken celle som ligger bak. Da kan nabokorn av samme mineral slås sammen til større, uregelmessige korn, og bare korngrensene tegnes (`Steinprove`). `naboAvstand` begrenser hvilke punkter som sjekkes (standard alle). Ren funksjon.
- **voronoiCeller**(punkter, boks, naboAvstand?) → `P[][]`: Voronoi-cellene til punktene innenfor boksen: hver celle er området som ligger nærmere sitt punkt enn noe annet. Gir en mosaikk av korn som griper inn i hverandre, som krystallene i granitt eller marmor (`Steinprove`). `naboAvstand` begrenser hvilke punkter som sjekkes (standard alle). Ren funksjon; `voronoiMosaikk` gir også naboene.
- **KORN_TEGNESKALA**: Kornene tegnes litt større enn sirkelen de pakkes som (omrisset ligger ellers helt innenfor), så nabokorn berører hverandre. Porøsiteten regnes med samme størrelse.
- **porositetEtterSortering**(sigma) → `number | null`: Omtrentlig porøsitet (0–1) i løst pakket, vannmettet sand med sorteringen σ (φ-enheter, Folk og Ward): fra ca. 42 % for svært godt sortert til ca. 28 % for svært dårlig sortert (Beard og Weyl 1973). Utenfor tabellen brukes endene. Ugyldig eller negativ σ gir null. `Kornpakning` bruker den til hvor mye finstoff som fyller porene.
- **pakkKorn**(valg) → `PakketKorn[]`: Pakker korn tett i en boks, som i en sandstein eller et sediment: kornene får tilfeldige plasser og vokser gradvis mens de skyves fra hverandre, til de ligger tett inntil hverandre uten å overlappe (tilfeldig tett pakking). Kornstørrelsene følger sorteringen σ (i φ-enheter, som Folk og Ward, regnet på massen): godt sorterte masser har like store korn, dårlig sorterte noen store og mange små. Til slutt fyller små korn (finstoff) porene, så porøsiteten faller med sorteringen omtrent som i `porositetEtterSortering`. Kornene fyller også litt utenfor boksen, så kantene av et utsnitt ikke blir tomme. Fast frø gir samme pakking hver gang. Ren funksjon; ugyldige mål gir en tom liste.
- **porositetIUtsnitt**(korn, utsnitt, rundhet?, n?) → `number | null`: Porøsiteten i et utsnitt av en pakking: andelen (0–1) av punktene i et rutenett (n × n over utsnittet) som ikke ligger i noe korn. Kornformene er `kornOmriss` med samme rundhet og frø som i tegningen, så tallet passer til figuren (et snitt gjennom kornene, som i et tynnslip). Ugyldig utsnitt gir null.
- **Korn**: Ett korn sett fra siden med lys fra øvre venstre: kantete korn har skarpe hjørner og lyse og mørke fasetter, runde korn er jevne med glans, som stein fra en elv eller strand. Fargen er bergartens (`GEO.bergart[type]`). Størrelsen ganges med `useGeoScale`, så små korn synes på mobil. `<Korn x={120} y={80} d={36} rundhet="kantet" type="granitt" flekker={5} /> <Korn x={300} y={bunnY} d={60} anker="bunn" skygge fastStorrelse />   // ligger på bunnen av elva` Ankerpunkt: (x, y) er midten av kornet (kornet ligger innenfor en sirkel med radius d/2, ganget med useGeoScale), eller det laveste punktet med `anker="bunn"`.
  - Props: `x`, `y`, `d = 40`, `rundhet?: number | RundhetId`, `avlang?`, `type?: MonsterId`, `farge?`, `kant?`, `seed = 1`, `rotate = 0`, `flekker = 0`, `skygge?`, `anker: 'midt' | 'bunn' = 'midt'`, `fastStorrelse?`, `dim?`, `title?`
- **PORE_NAVN** (`Record<PoreFyll, string>`): Navnene til forklaringer og knapper.
- **poreFarge**(fyll) → `GeoPaint`: Fargen på væsken eller gassen i porene (lyst og mørkt tema). Sement er kalkspat, leire er vann med leirpartikler.
- **kornpakningGeometri**(v, k?) → `KornpakningGeometri | null`: Kornene i en `Kornpakning` uten å tegne dem: til strømlinjer gjennom porene, merker på enkeltkorn eller porøsiteten i en model.ts. `k` er `useGeoScale()` (kornene vokser på mobil). Ren funksjon.
- **Kornpakning**: Forstørret utsnitt (lupe) av pakkede korn med porene mellom: vann, olje, gass, CO₂, luft, sement eller leire. Kornene legger seg som når de synker i vann (`pakkKorn`), med sorteringen som prop: godt sorterte masser har like store korn og store porer, dårlig sorterte har små korn i hullene og lavere porøsitet. Olje, gass og CO₂ tegnes med en vannhinne rundt kornene (vannfuktet bergart), luft med vann i kontaktene (umettet sone). Fast frø gir samme bilde. `<Kornpakning x={200} y={160} r={120} fyll="olje" sortering={0.4} rundhet="rundet" />` Ankerpunkt: (x, y) er midten av utsnittet (sirkel med radius r, eller rektangel w × h).
  - Props: `x`, `y`, `r?`, `w?`, `h?`, `korn?`, `sortering?`, `rundhet?: number | RundhetId`, `seed?`, `fyll: PoreFyll = 'vann'`, `vannfilm?`, `sement?`, `leire?`, `type: MonsterId = 'sand'`, `blandet = true`, `ramme = true`, `malestokk?: { lengde: number; tekst: string }`, `children?: ReactNode | ((g: KornpakningGeometri) => ReactNode)`, `dim?`
- **Malestokk**: Liten målestokk med tekst over, sentrert om x (til Kornpakning og Lupe). `y` er streken. Hvit glorie, så den synes på korn og porer i begge temaer.
  - Props: `x`, `y`, `lengde`, `tekst`, `farge = VIZ.ink`
- **fmtMm**(d) → `string`: Diameter i mm med passe mange desimaler: 25, 2,5, 0,15, 0,012.
- **Kornkurve**: Kumulativ kornfordeling (prosent gjennomgang mot kornstørrelse på logaritmisk akse) som i en sikteanalyse, med kornklassene leire, silt, sand og grus (og stein) som bånd og navnene over diagrammet. Kurvene får prikker ved siktene, og persentiler (d₁₀, d₆₀ …) kan leses av med stiplede linjer. Bygd på `LogPlot`; høyden vokser på mobil. `<Kornkurve kurver={[{ punkter: kumulativKurve(sikter, masser, bunn)!, navn: 'Prøve A' }]} persentiler={[10, 60]} />` Ankerpunkt: `at` er øvre venstre hjørne (standard 0, 0).
  - Props: `at?: readonly [number, number]`, `kurver: readonly KornkurveSerie[]`, `width = 800`, `height?`, `dMin = 0.001`, `dMax = 100`, `baand = true`, `persentiler?: readonly number[]`, `persentilKurve = 0`, `sikter?: readonly number[]`, `forklaring?`, `forklaringPlass: 'auto' | 'oppe-venstre' | 'nede-hoyre' | 'under' = 'auto'`, `children?: (s: LogPlotSkalaer) => ReactNode`
- Typer: `RundhetId = 'svaert-kantet' | 'kantet' | 'kantrundet' | 'noe-rundet' | 'rundet' | 'godt-rundet'`, `Rundhetsklasse { id, navn, verdi }`, `KornOmriss { hjorner, avrunding, kontur, spisser }`, `KornOmrissValg { rundhet?, avlang?, seed? }`, `VoronoiMosaikk { celler, naboer }`, `PakketKorn { x, y, r, seed, rotate, u }`, `PakkKornValg { w, h, r, sortering?, seed?, maks?, rundhet? }`, `Utsnitt`, `KornProps`, `PoreFyll = 'vann' | 'olje' | 'gass' | 'co2' | 'luft' | 'sement' | 'leire'`, `KornpakningGeometri { korn, kontakter, utsnitt, kornRadius, porositet }`, `KornpakningGeometriValg { x, y, r?, w?, h?, korn?, sortering?, rundhet?, seed? }`, `KornpakningProps`, `KornkurveSerie { punkter, navn?, farge?, stiplet?, merker?, dim? }`, `KornkurveProps`

## stein.tsx
Stein og mineraler i geofagfigurene: krystaller i 3D med glans og valgfrie isotopprikker (`Krystall`), håndstykker med teksturen til bergarten (`Steinprove`: kornstørrelse, porfyr, glass, blærer, lag, fossiler, foliasjon og bånd) og en lupe som forstørrer et utsnitt (`Lupe`).

- **mineralFarge**(mineralEllerTone) → `MineralFarge`: Fargen til et mineral eller en mineraltone (`MINERALER[id].tone`) i begge temaer: fyll, kant, gjennomsiktig (kvarts, flusspat) og metall (pyritt, blyglans, gull). Til egne mineralkorn i kapitlene: `const c = mineralFarge('biotitt');  <path d={…} fill={c.fill} stroke={c.line} />`
- **KRYSTALLFORM_NAVN** (`Record<Krystallform, string>`): Navnene på krystallformene til knapper og forklaringer.
- **KRYSTALLFORMER** (`readonly Krystallform[]`): Alle krystallformene i fast rekkefølge.
- **konveksInnhylling**(punkter) → `P[]`: Konveks innhylling (monoton kjede), mot klokka i et vanlig koordinatsystem.
- **krystallGeometri**(form, valg?) → `KrystallGeometri | null`: Geometrien til en krystall sett skrått ovenfra med lys fra øvre venstre foran: flatene projisert (parallellprojeksjon), lyset og glansen på hver flate, striper (kvarts, pyritt, glimmer) og omrisset. Midten er (0, 0) og det største målet (bredde eller høyde) er 1, så komponenten bare ganger med størrelsen. Ren funksjon.
- **prikkerIPolygon**(polygon, n, avstand, seed?) → `P[]`: Inntil `n` punkter spredt jevnt inne i et (konvekst eller konkavt) polygon, med minst `avstand` mellom punktene og fra kanten. Samme frø gir samme punkter, og rekkefølgen er fast, så de første m punktene kan farges om én etter én (morisotoper som blir datterisotoper). Ren funksjon.
- **Krystall**: Krystall i 3D med lys fra øvre venstre: prisme (kvarts med sekskantet spiss, zirkon firkantet med spiss i begge ender), romboeder (kalkspat), terning (pyritt med striper, halitt, blyglans), oktaeder (magnetitt, flusspat), tavle (glimmer, biotitt, sanidin) og rombedodekaeder (granat). Fargen kommer fra mineralets tone (`mineralFarge`), og glansen styrer lys og skygge: metallglans gir sterk kontrast og et blankt lysfelt, glassglans gjennomsiktige flater der de bakre kantene synes. Valgfrie isotopprikker viser morisotop (`GEO.morIsotop`) og datterisotop (`GEO.datterIsotop`). `<Krystall x={120} y={90} mineral="zirkon" size={80} isotoper={0.5} />` Ankerpunkt: (x, y) er midten av krystallen (midt i omrisset). Størrelsen ganges med `useGeoScale`.
  - Props: `x`, `y`, `form?: Krystallform`, `mineral?: MineralId`, `tone?: MineralTone`, `glans?: Glans`, `size = 70`, `fastStorrelse?`, `isotoper?: number | KrystallIsotoper`, `skygge?`, `dim?`, `title?`, `dreiing?`, `helning?`, `vipp?`, `forlengelse?`, `sider?: 4 | 6`, `dobbel?`
- **steinproveGeometri**(v) → `SteinproveGeometri | null`: Formen på en steinprøve med bunnen midt på (x, y) og bredden `size`, sett skrått ovenfra med lys fra øvre venstre: kantet er en uregelmessig klump med noen få, brede bruddflater (konveks innhylling av tilfeldige punkter på en flattrykt, kantete kule med flat underside, der nesten like flater er slått sammen), rundslipt er en rullestein med jevnt omriss. Ren funksjon; samme frø gir samme stein.
- **Steinprove**: Håndstykke av en bergart sett skrått ovenfra, med teksturen til bergarten: grove, sammenvokste krystaller (granitt, gabbro, larvikitt med blått skimmer), fin grunnmasse med store krystaller (porfyr, rombeporfyr med romber), glass med skjellformet brudd (obsidian), blærer (basalt), rullestein i sand (konglomerat), lag og fossiler (kalkstein med ortoceratitt, leirskifer med graptolitter), foliasjon med glimmerglans og granater (glimmerskifer) og lyse og mørke bånd (gneis). Kantet har bruddflater med lys toppflate og mørkere forside; rundslipt er en blank rullestein. `<Steinprove x={200} y={240} bergart="rombeporfyr" size={160} />` Ankerpunkt: (x, y) er midt under prøven, på underlaget. Bruk `steinproveGeometri` for midten av toppflaten.
  - Props: `x`, `y`, `bergart: BergartId`, `size = 150`, `form: SteinForm = 'kantet'`, `kornstorrelse = 1`, `fossiler?`, `blaerer?`, `lag?`, `seed = 1`, `skygge = true`, `flip?`, `dim?`, `title?`
- **lupeKjegle**(fra, lupe) → `[[P, P], [P, P]] | null`: De to ytre tangentene mellom en liten sirkel (stedet som forstørres) og en stor (lupen): [[punkt på liten, punkt på stor], …], til strekene fra stedet ut til lupen. Null når den ene sirkelen ligger inni den andre. Ren funksjon.
- **Lupe**: Lupe som forstørrer et utsnitt: innholdet (children) tegnes i linsa, klippet til sirkelen, med glassrefleks og en mørkere kant. Med `fra` viser en ring og to streker hvor utsnittet er hentet fra (som i lærebøker). Stilen 'lupe' har ramme og håndtak, 'boble' bare en tynn ring. Innholdet er enten noe nytt i linsas koordinater (korn og porer i en steinprøve, leirpartikler i kvikkleire) eller, med `forstorr`, den samme figuren forstørret (krystallene i granitt). `<Lupe x={560} y={130} r={100} fra={{ x: 240, y: 200, r: 14 }}>{({ r }) => <Kornpakning x={0} y={0} r={r} ramme={false} />}</Lupe> <Lupe x={300} y={150} r={70} handtak={130} forstorr={{ faktor: 2.5 }}>{stein}</Lupe>   // rett over steinen` Ankerpunkt: (x, y) er midten av linsa.
  - Props: `x`, `y`, `r`, `fra?: { x: number; y: number; r?: number }`, `stil?: 'lupe' | 'boble'`, `handtak = 45`, `bakgrunn?`, `tekst?`, `malestokk?: { lengde: number; tekst: string }`, `forstorr?: { faktor: number; x?: number; y?: number }`, `children?: ReactNode | ((l: { r: number; k: number }) => ReactNode)`, `dim?`
- Typer: `MineralFarge { gjennomsiktig, metall, fill, line }`, `KrystallFlate { punkter, lys, glans, synlig, del, striper }`, `KrystallGeometri { flater, omriss, bredde, hoyde }`, `KrystallFormValg { dreiing?, helning?, vipp?, forlengelse?, sider?, dobbel? }`, `KrystallIsotoper { n?, datter, seed? }`, `KrystallProps`, `SteinForm = 'kantet' | 'rundslipt'`, `SteinproveFlate { punkter, lys, opp }`, `SteinproveGeometri { omriss, flater, kanter, midt, topp, venstre, hoyre, bredde, hoyde }`, `SteinproveProps`, `LupeProps`
