# SmartNotes – notes for Claude

Personal app for a Norwegian student: handwritten lecture notes (photos/PDF) → Claude vision → LaTeX → PDF, organised by subject → textbook chapter → section. Subjects so far: Fysikk 1, Kjemi 1, Biologi 1 (VG2, LK20). Offline-first PWA + one Docker server that syncs devices. UI text, error messages and the PDF template are **Norwegian bokmål**; code identifiers are English.

## Layout
- `shared/src/index.ts` – API contract (types only; import with `import type`).
- `server/` – Fastify + better-sqlite3. `src/app.ts` wires everything; routes in `src/routes/`; `src/db.ts` holds all SQL (`Repo`).
  - Sync: every row change gets a new global `rev` (`Repo.nextRev()`); `GET /api/sync?since=` returns rows with `rev > since` incl. soft-deleted tombstones. Any new mutation MUST bump `rev`.
  - Schema changes: append a new SQL string to `MIGRATIONS` in `src/db.ts` (never edit old ones; applied via `PRAGMA user_version`), then update the row type + `toX` mapper, `Repo.sync`, `SyncResponse` in `shared`, and the apply code in `web/src/sync.ts`. On the client add `db.version(n+1)` in `web/src/db.ts`; when synced rows gain fields or a synced table is added, its `upgrade` must reset `meta.syncCursor` to 0 so devices do a full resync (see versions 3 and 4).
  - Pipeline (`src/pipeline/`): `worker.ts` (DB-backed queue) → `converter.ts` (pages → Claude → crop figures → sanitize → `latex.ts` compile → fix loop → save). `bundle.ts` = combined chapter/subject PDFs.
  - AI layer: `pipeline/ai.ts` holds the provider-neutral `AiService` interface, request types and shared prompt pieces (`buildContext`, `TOC_AIMS_PROMPT`, `tocSchema`). `pipeline/providers.ts` → `createAi(config, wrap)` picks a provider per task (`AI_PROVIDER`, `AI_PROVIDER_CONVERT|_FLASHCARDS|_TOC`; fix follows convert, aims follow toc) and returns one service or a `RoutedAi`; `aiConfigured(ai, task)` checks the provider of that task; `describeAi` feeds `/api/health` (`ai`). Providers: `AnthropicClaude`/`FakeClaude` (`claude.ts`) and `OllamaAi` (`pipeline/ollama.ts`: Ollama `/api/chat` streamed as NDJSON (Node's fetch gives up after 300 s without response headers), `think: false` unless `OLLAMA_THINK`, `num_ctx` grown per call from an estimate up to `OLLAMA_MAX_CTX`, same prompts and `<metadata>/<latex>` format for convert/fix, JSON schema (`format`) for toc/aims/flashcards with `repairLatexEscapes` after parsing (a small model's `\frac` in JSON arrives as form feed + «rac»), one page per convert call by default (`OLLAMA_PAGES_PER_CALL`, parts joined by `mergeParts`, which renumbers figure ids), page images downscaled to `OLLAMA_IMAGE_MAX_EDGE` (multiples of 28 px in pixel mode, as Qwen-VL patches them) and figure boxes scaled back (`OLLAMA_BOX_UNITS` thousandths (default, Qwen3/3.5) | thousandths-yx | pixels), Norwegian errors). Every provider sets `provider` and returns `usage` on all methods.
  - Home worker (`src/remote/`): provider `remote` = `RemoteAi`, which puts each AI call in the in-memory `RemoteHub` queue; the home machine (`npm run homeworker`, `remote/homeworker.ts`, runs `OllamaAi` locally) long-polls `POST /api/worker/claim` (bearer `WORKER_TOKEN` checked in `onRequest`, bypasses the cookie auth in `auth.ts`), keeps a 60 s lease alive with heartbeats (each claim has a random `lease` id that heartbeat/result must send) and posts the result. Results are zod-checked, and convert meta goes through `parseMeta` again because figure ids become file names. Expired leases go back to the queue (max 3 claims), a call running longer than `REMOTE_MAX_RUN_MS` is stopped, unclaimed calls give up after `REMOTE_MAX_WAIT_MS`, TOC/aims calls fail fast when no worker is online. With `REMOTE_FALLBACK=anthropic` the hub gives up as soon as no worker is online (also for calls already waiting, outcome code `unavailable`) and `RemoteWithFallback` reroutes to Claude. Deleting a note cancels its calls (`hub.cancel`); on shutdown the hub aborts calls with `AbortedError`, which the converter and the flashcard generator ignore (no DB writes; `resetInterrupted` requeues on start). While a convert call waits, the note's stage is `waiting` (hooks in `app.ts`, note id from `usageScope`). Protocol in `remote/protocol.ts` (`PROTOCOL_VERSION`, bump on format changes). Status for Settings: `GET /api/ai/status`. Guide: `docs/HJEMMEMASKIN.md`.
  - Claude: `pipeline/claude.ts` (one model per task in `config.claudeModels`: conversion + fix `CLAUDE_MODEL` = `claude-sonnet-5-5` with effort `medium`, flashcards `CLAUDE_MODEL_FLASHCARDS` and TOC/aims `CLAUDE_MODEL_TOC` = `claude-haiku-5-5`, chosen by the user for cost on 12 Oct 2026; `createAi` builds one `AnthropicClaude(config, model)` per model, and because Haiku has no server-side fallback, a Haiku task is wrapped in `RefusalFallback`, which retries a `RefusalError` (stop_reason `refusal`) on the conversion model; `AnthropicClaude` streaming + adaptive thinking + `fallbacks: 'default'`; `FakeClaude` for dev/tests via `SMARTNOTES_FAKE_CLAUDE=1`). Output format = `<metadata>{json}</metadata><latex>body</latex>` parsed in `parse.ts`. Every call sends adaptive thinking + `output_config.effort` (+ the server-side fallback beta), and `pipeline/images.ts` sizes pages (2576 px long edge, 3.6 MP) so figure boxes are 1:1 with page pixels. Page image blocks set `transformations: { oversized_image: 'error' }`, so a model that would downscale them (standard-res tier) is rejected with a Norwegian error instead of misplacing crops. So `CLAUDE_MODEL` must support high-res vision, adaptive thinking and effort; the Opus/Sonnet/Haiku 5.5 models do (Haiku 5.5 is high-res, unlike Haiku 4.5). Check a cheaper or older model against these before suggesting it.
  - Usage log (`src/usage.ts`): `buildApp` wraps the AI service in `MeteredAi`, which writes one `usage_log` row per call (also failed ones: errors raised after the model answered carry `ConversionError.usage` via `withUsage`). What a call belongs to (note, deck, subject) comes from `usageScope(...)` (AsyncLocalStorage) around the work in the converter, flashcard generator and TOC routes. `GET /api/usage?days=` summarises cost at list price (`MODEL_PRICES`, `USD_NOK`, local/fake = 0); shown in Settings → «Forbruk av AI». Server-only table, not synced.
  - Backup (`src/backup.ts`, `routes/backup.ts`): `GET /api/backup` streams a `.tar.gz` (own ustar + pax writer, gzip level 1) with a consistent DB copy (`Repo.backupTo`: SQLite backup API, sessions removed, `journal_mode = DELETE`), `LES-MEG.txt` (restore steps: stop server, delete `-wal`/`-shm`, swap in DB + `notes/`), a `sikkerhetskopi.json` manifest and every file under `notes/`, hard-linked into `tmp/backup-*` when the request starts so deletes/edits/reconverts during the download don't change the archive (not `bundles/`, `tmp/` or `*.tmp`; a new data folder must be added to the archive). That only holds if files under `notes/` are never rewritten in place: write them with `writeFileAtomic` (`storage.ts`) or rename, never plain `fsp.writeFile`. `meta.last_backup_at` («Sist sendt fra serveren») is set when the response finishes, which is not proof the device saved the file; no HEAD route (it would snapshot for nothing). `GET /api/backup/status` feeds Settings → «Sikkerhetskopi», which polls until the download is done. Restore is not built yet (Railway volume backups need the Pro plan); after a restore the server's `rev` is lower than the devices' cursors, and `pull()` in `web/src/sync.ts` then replaces all local rows instead of keeping «newer» ones, and clears cached PDFs (a `pdfRev` can mean other content after a restore). The Docker entrypoint chowns `/data` when any file there is not owned by `node`.
  - Model comparison (`pipeline/compare.ts`, `routes/compare.ts`): «Prøv med Haiku» re-converts a finished note with `COMPARE_MODEL` (`claude-haiku-5-5`, a bare metered `AnthropicClaude`, deliberately without `RefusalFallback` so a refusal never shows a Sonnet PDF as Haiku's; tests pass `compareAi`). `Comparer.start` sets the row to running before its first `await`, copies `pages/` into `tmp/compare-*`, then runs one at a time: `Converter.buildConvertRequest` (same input as the real conversion), `cropFiguresInto`, `compileInto` (same template and title block via `docInfo`) and the same fix loop, and finally swaps the result into `notes/<id>/compare/haiku/` with a rename (no recursive mkdir, so a note deleted meanwhile is not recreated). It never touches the note row, its files, `rev` or sync. Server-only tables `note_comparisons` (one row per note with the `prompt_version` it was made with; running rows are marked failed on restart instead of re-run, since it costs money) and `comparison_ratings` (rating `haiku_ok`/`sonnet_better` + comment per note and instruction version, so Settings counts only ratings of the current version and lists older versions separately). Usage is logged under the note via `usageScope`. Haiku instructions (`profiles/haiku.ts`): `systemPromptFor(profile, model)` appends the subject's `haikuAddendum` (section 7: latex before metadata, named formel boxes, merknad only for certain errors, `samlet` around calculations, TikZ templates for physics, a full example answer, checklist) only for `claude-haiku*` models, and `convert` ends with `HAIKU_CLOSING` instead of the usual last line; Sonnet/Opus prompts are unchanged. The comparison runs Haiku with `COMPARE_EFFORT` high, `COMPARE_MAX_TOKENS` 128 000 and at least `COMPARE_FIX_ATTEMPTS` 3 fix rounds. Changing any of these (or the addendum text) means bumping `HAIKU_PROMPT_VERSION` and the fingerprint in `test/haiku.test.ts`, which also compiles every template and the example answer per subject. Web: menu item on the note page → `/notat/:id/sammenlign` (`ComparePage`), summary card in Settings (`GET /api/compare/summary`).
  - Subject profiles (`SubjectProfile` = `physics` | `chemistry` | `biology`): `src/profiles/<id>.ts` (system prompt – keep it free of dates/ids so it caches; `tocPrompt` via `toc-prompt.ts`) + `latex/<id>/preamble.tex` (physics «Klassisk», chemistry «Moderne» with mhchem/chemfig, biology «Lærebok»). Register new ones in `profiles/index.ts`, `shared` and `web/src/lib/subjects.tsx`.
  - Subject presets: `src/presets.ts` (`SUBJECT_PRESETS`: LK20 competence aims from Udir (public, NLOD) plus SmartNotes' OWN topics → subtopics → aims; no textbook names or textbook tables of contents, for copyright reasons; users import their own book's TOC privately). Old ids (`ergo-fysikk-1` …) are `aliases`, so a DB seeded with them is not seeded again; `findPreset` resolves them. `SEED_TEXTBOOKS` (comma list, default all, `none` = blank «Fysikk») seeds each preset once (meta key `seeded_presets`), also into an existing DB. Sections live as JSON on `chapters.sections`, aims on `subjects.aims`; a note stores only its section code, and its aims are derived from the section. Claude picks chapter + section; the server validates the section against the chapter.
  - Table of contents import (`src/toc.ts`, routes `/chapters/parse|extract|bulk`): text or photos → chapters with sections; Claude maps sections to the subject's aims (`mapSectionAims`, or inside `extractToc`). The web preview (`pages/settings/ChapterImport.tsx`) updates existing chapters (same number) instead of duplicating them.
  - `notes.search_text` = `latexToText(body)`, synced to the client for offline search.
  - LaTeX safety: compile with `latexmk -no-shell-escape`, `openin_any=p`, `openout_any=p`; `sanitizeBody` strips file/preamble commands.
  - Normalizer (`normalizeBody` in `latex.ts`, run by `sanitizeBody` for every model, outside TikZ/circuitikz code): `35 %` → `35\,\%` (a bare `%` silently drops the rest of the line), `løsning` → `losning`, a title on husk/merknad/losning moves into the box, a repeated «Eksempel:»/«Oppgave»/«Definisjon:» is stripped from titles, figure/table get `[H]`, blank lines inside display math are removed, `\caption` in a center block becomes `\captionof{figure}`. Only patterns that never compile or print right are touched; keep it that way. `EXTRA_PREAMBLE` adds `samlet` (keeps a block on one page, splits it normally when taller than 0.85 `\textheight`, so nothing is lost), a math-safe `\uleselig` and English aliases (`solution`, `definition`, `example`, `exercise`). `parseMeta` repairs LaTeX in metadata strings (lone backslashes doubled, `\f`/`\b`/`\t` in math restored via `repairLatexEscapes`) instead of dropping all metadata (and with it every figure).
- `web/` – React 19 + Vite 8 PWA (vite-plugin-pwa), Dexie as local source of truth (files stored as Blob or ArrayBuffer, see `storable()` in `db.ts`, because WebKit cannot store Blobs in private mode), outbox for offline uploads, pdf.js viewer. App updates (`lib/pwa.ts`): Workbox `autoUpdate` + own `controllerchange` listener; the build id (`<meta name="smartnotes-build">`, content hash set in `vite.config.ts`) is sent back by the server on every API response (`X-SmartNotes-Build`), so a page still running an old build notices and shows «En ny versjon …» (reload on next navigation); tested in `e2e/oppdatering.spec.ts` (also WebKit). Three-column layout ≥1180px (sidebar | list pane | content), search palette (Ctrl/Cmd+K), light/dark/system theme via `data-theme`, colour theme per subject via `data-subject` (`styles/subjects.css`: chemistry «Tavle», biology «Salvie»; set by `AppShell` → `setSubjectTheme`, and early in `index.html` to avoid a flash).
- Visualizations (`web/src/viz/`, read `web/src/viz/README.md` first): interactive explanations per textbook chapter, pages `/fag/:id/visualiseringer[/:vizKey]`. Per subject type: `fysikk/`, `kjemi/`, `biologi/`, each with one folder per chapter `kapNN/` (`index.ts` meta list, `model.ts` pure model + `model.test.ts`, one component per viz); shared building blocks in `kit/` (subject extras in `kjemi/kit/` and `biologi/kit/`; chemistry and biology use `sections: []` for chapters whose sections are not confirmed yet, i.e. all except Kjemi 1 chapter 1, whose four visualizations are linked to 1.2–1.5); `registry.ts` maps profile → entries (`vizEntries(profile)`, `getViz(profile, key)`); keys `k{chapter}-{id}` are unique per profile. Illustrated realism (physics ch. 1–4 so far): scene kit `kit/scene/` (palette `--sc-*`, materials, shadows, `ForceArrow`, families bakgrunn/kjoretoy/figurer/mekanikk/lab/rom; import from `../../kit/scene`, overview in generated `kit/scene/API.md`, gallery `/viz-preview.html?galleri=…`). Worked examples: `WorkedExample` in `kit/eksempel.tsx`, meta `kind: 'eksempel'` and id starting with `eks-` (tested in `registry.test.ts`), own group on the pages; tasks must be original, never copied exam or textbook tasks. Work plan and remaining chapters: `docs/VISUALISERINGER-PLAN.md`; the Workflow scripts, per-chapter catalogs and how to run/resume them: `docs/workflows/README.md`. Dev preview without server/login: `/viz-preview.html?fag=kjemi&id=k3-stoffmengde&theme=dark`; screenshots: `node web/scripts/viz-shot.mjs [--fag kjemi] --chapter N [--extremes]`.
- Flashcards: server tables `decks` + `cards` (synced rows; a card's `level` 0–3 + `levelAt`), generation in the background by `server/src/flashcards/generator.ts` (prompt in `prompt.ts`, `claude.generateFlashcards`; difficulty steers both card kind and answer length), routes in `routes/flashcards.ts`. Progress from practice goes through `POST /api/flashcards/progress` (last `levelAt` wins, best streak = max); on the client it is written to Dexie at once and queued in the `progress` table (`flushProgress` in `web/src/sync.ts`), so practice works offline. Practice rules mirror the user's earlier flashcard file and live in `web/src/flashcards/model.ts` (tested); the UI is `Practice.tsx`, pages `/fag/:id/flashcards[/ny|/:deckId]`. Card text uses `**bold**`, `$TeX$` (KaTeX + mhchem, lazy-loaded) and «!» label lines. Repetition is only a choice after the round (misses / misses + uncertain / all), no cross-day scheduling.
- UI conventions (from the user's earlier project Momentum, `/home/user/momentum` if cloned): sentence case everywhere (no ALL CAPS labels), no emojis, calm UI, CSS variables only.

## Commands
- `npm test` (server vitest, needs TeX Live incl. `texlive-plain-generic` for chemfig, + poppler; plus web vitest for the viz models), `npm run typecheck`, `npm run build`, `npm run test:e2e` (Playwright, Chromium desktop + mobile), `npm run test:e2e:webkit` (Safari/iPad, own CI job). `test:e2e` runs the built `server/dist` + `web/dist`, so run `npm run build` first.
- Fresh container: TeX Live is not preinstalled. Before `npm test` run `sudo apt-get update && sudo apt-get install -y --no-install-recommends texlive-latex-base texlive-latex-recommended texlive-latex-extra texlive-science texlive-pictures texlive-plain-generic texlive-lang-european texlive-fonts-recommended lmodern latexmk poppler-utils` (same list as `.github/workflows/ci.yml`).
- Deploy: Railway (`railway.json`, Dockerfile, volume on `/data`, variables `APP_PASSWORD`, `ANTHROPIC_API_KEY`, `PORT=8080`, auto-deploy from `main` with Wait for CI). Step-by-step for the user: `docs/OPPSETT.md`; Fly.io/Docker alternatives in `docs/DEPLOY.md`. The image starts as root only to chown the volume (`scripts/docker-entrypoint.sh`), then runs as `node`.
- Dev: `SMARTNOTES_FAKE_CLAUDE=1 npm run dev` (server :8787, web :5173 with /api proxy).
- Mutating API calls require header `X-SmartNotes: 1`; auth is the `sn_session` cookie. The auth hook in `auth.ts` decides by the matched route (`req.routeOptions.url`), never the raw URL, because the router decodes `%61pi` to `api`.
