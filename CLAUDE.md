# SmartNotes – notes for Claude

Personal app for a Norwegian student: handwritten lecture notes (photos/PDF) → Claude vision → LaTeX → PDF, organised by subject → textbook chapter → section. Subjects so far: Fysikk 1, Kjemi 1, Biologi 1 (VG2, LK20, seeded) and Geofag 1 (added by the user with «Legg til fag»). Offline-first PWA + one Docker server that syncs devices. UI text, error messages and the PDF template are **Norwegian bokmål**; code identifiers are English.

## Layout
- `shared/src/index.ts` – API contract (types only; import with `import type`).
- `server/` – Fastify + better-sqlite3. `src/app.ts` wires everything; routes in `src/routes/`; `src/db.ts` holds all SQL (`Repo`).
  - Sync: every row change gets a new global `rev` (`Repo.nextRev()`); `GET /api/sync?since=` returns the user's rows with `rev > since` incl. soft-deleted tombstones (and `userId`). Any new mutation MUST bump `rev`.
  - Accounts (`src/auth.ts`, `src/passwords.ts`, `routes/admin.ts`, migration 7): `users` (id 1 = the owner, plan `owner` | `free`, `pro` later; the owner logs in with `APP_PASSWORD` and an empty username or their own, `eier` until renamed with `PATCH /api/admin/me`; others with scrypt hashes, N=16384, at most 2 at a time), `user_sessions` (the old `sessions` table stays for a rollback), `user_devices` (cookie `sn_device`, path `/api/auth`: a device that logged in before is exempt from the per-account lock of 10 failures in 15 min), `invites` (code shown once, stored as sha256, 14 days, one use) and `password_resets` (one-time link the owner makes, 48 h, logs the user out everywhere). Every user table has `user_id INTEGER NOT NULL DEFAULT 1` (no foreign key; a row an older server writes after a rollback belongs to the owner) with triggers that forbid changing it, so the global `rev` cursor still works per user. Routes never touch user data through `Repo`: `repo.forUser(requireUser(req).id)` gives a `UserRepo` that checks ownership first and returns null/false/[] (→ 404). `ROUTE_ACCESS` in `auth.ts` gives every /api route `public` | `user` | `owner` | `worker`; the server refuses to start when one is missing (`onRoute`), `owner` routes answer 404 to others, and `test/accounts.test.ts` has a case per route (a new route needs one) where users try each other's ids in four directions. A request whose `X-SmartNotes-Account` is not the session's user gets 409. `trustProxy` trusts `TRUST_PROXY_HOPS` hops (1 on Railway). Login limits: 10 per IP and username and 50 per IP per 15 min, and a per-account lock (10 failures from unknown devices in 15 min, also for the owner with an empty username; unknown usernames get the same lock in memory); each attempt is counted before the scrypt await (refunded on success), so parallel guesses cannot slip past, the lock is checked before the password so the answer is the same for a right and a wrong one, and a long scrypt queue answers 503. Registration and reset: 10 failures per IP per hour. Free users convert with `FREE_CONVERT_MODEL` (Haiku via Anthropic, `createFreeConvertAi`, effort high, at least 3 fix rounds, `RefusalFallback` to `CLAUDE_MODEL`) whatever `AI_PROVIDER_CONVERT` says, chosen in `Converter.aiFor` by the plan of the note's owner; flashcards and TOC use the same AI for everyone. Background jobs attribute usage with `jobScope` (not inherited from the request that kicked the queue); `usage_log` has `user_id` and `pages`. Owner only: comparison, backup, usage, AI status and admin. Disabling an account deletes its sessions, known devices and reset links and cancels every home-worker call whose `ref.userId` is the user; the note queue skips disabled users, and the flashcard generator fails a deck of a disabled user before the AI call and before saving the cards. A password reset also forgets the known devices.
  - Schema changes: append a new SQL string to `MIGRATIONS` in `src/db.ts` (never edit old ones; applied via `PRAGMA user_version`), then update the row type + `toX` mapper, `Repo.sync`, `SyncResponse` in `shared`, and the apply code in `web/src/sync.ts`. On the client add `db.version(n+1)` in `web/src/db.ts`; when synced rows gain fields or a synced table is added, its `upgrade` must reset `meta.syncCursor` to 0 so devices do a full resync (see versions 3 and 4).
  - Pipeline (`src/pipeline/`): `worker.ts` (DB-backed queue) → `converter.ts` (pages → Claude → crop figures → sanitize → `latex.ts` compile → fix loop → save). `bundle.ts` = combined chapter/subject PDFs.
  - AI layer: `pipeline/ai.ts` holds the provider-neutral `AiService` interface, request types and shared prompt pieces (`buildContext`, `TOC_AIMS_PROMPT`, `tocSchema`). `pipeline/providers.ts` → `createAi(config, wrap)` picks a provider per task (`AI_PROVIDER`, `AI_PROVIDER_CONVERT|_FLASHCARDS|_TOC`; fix follows convert, aims follow toc) and returns one service or a `RoutedAi`; `aiConfigured(ai, task)` checks the provider of that task; `describeAi` feeds `/api/health` (`ai`). Providers: `AnthropicClaude`/`FakeClaude` (`claude.ts`) and `OllamaAi` (`pipeline/ollama.ts`: Ollama `/api/chat` streamed as NDJSON (Node's fetch gives up after 300 s without response headers), `think: false` unless `OLLAMA_THINK`, `num_ctx` grown per call from an estimate up to `OLLAMA_MAX_CTX`, the subject's base prompt (`profile.systemPrompt`, without the precise rules Claude gets) and the `<metadata>/<latex>` format for convert/fix, JSON schema (`format`) for toc/aims/flashcards with `repairLatexEscapes` after parsing (a small model's `\frac` in JSON arrives as form feed + «rac»), one page per convert call by default (`OLLAMA_PAGES_PER_CALL`, parts joined by `mergeParts`, which renumbers figure ids), page images downscaled to `OLLAMA_IMAGE_MAX_EDGE` (multiples of 28 px in pixel mode, as Qwen-VL patches them) and figure boxes scaled back (`OLLAMA_BOX_UNITS` thousandths (default, Qwen3/3.5) | thousandths-yx | pixels), Norwegian errors). Every provider sets `provider` and returns `usage` on all methods.
  - Home worker (`src/remote/`): provider `remote` = `RemoteAi`, which puts each AI call in the in-memory `RemoteHub` queue; the home machine (`npm run homeworker`, `remote/homeworker.ts`, runs `OllamaAi` locally) long-polls `POST /api/worker/claim` (bearer `WORKER_TOKEN` checked in `onRequest`, bypasses the cookie auth in `auth.ts`), keeps a 60 s lease alive with heartbeats (each claim has a random `lease` id that heartbeat/result must send) and posts the result. Results are zod-checked, and convert meta goes through `parseMeta` again because figure ids become file names. Expired leases go back to the queue (max 3 claims), a call running longer than `REMOTE_MAX_RUN_MS` is stopped, unclaimed calls give up after `REMOTE_MAX_WAIT_MS`, TOC/aims calls fail fast when no worker is online. With `REMOTE_FALLBACK=anthropic` the hub gives up as soon as no worker is online (also for calls already waiting, outcome code `unavailable`) and `RemoteWithFallback` reroutes to Claude. Deleting a note cancels its calls (`hub.cancel`); on shutdown the hub aborts calls with `AbortedError`, which the converter and the flashcard generator ignore (no DB writes; `resetInterrupted` requeues on start). While a convert call waits, the note's stage is `waiting` (hooks in `app.ts`, note id from `usageScope`). Protocol in `remote/protocol.ts` (`PROTOCOL_VERSION`, bump on format changes). Status for Settings: `GET /api/ai/status`. Guide: `docs/HJEMMEMASKIN.md`.
  - Claude: `pipeline/claude.ts` (one model per task in `config.claudeModels`: conversion + fix `CLAUDE_MODEL` = `claude-sonnet-5-5` with effort `medium`, flashcards `CLAUDE_MODEL_FLASHCARDS` and TOC/aims `CLAUDE_MODEL_TOC` = `claude-haiku-5-5`, chosen by the user for cost on 12 Oct 2026; `createAi` builds one `AnthropicClaude(config, model)` per model, and because Haiku has no server-side fallback, a Haiku task is wrapped in `RefusalFallback`, which retries a `RefusalError` (stop_reason `refusal`) on the conversion model; `AnthropicClaude` streaming + adaptive thinking + `fallbacks: 'default'`; `FakeClaude` for dev/tests via `SMARTNOTES_FAKE_CLAUDE=1`). Output format = `<latex>body</latex><metadata>{json}</metadata>` for Claude since version 3 (section 7.1 of the precise rules; the base prompts and Ollama put metadata first), parsed in either order by `parse.ts`. Every call sends adaptive thinking + `output_config.effort` (+ the server-side fallback beta), and `pipeline/images.ts` sizes pages (2576 px long edge, 3.6 MP) so figure boxes are 1:1 with page pixels. Page image blocks set `transformations: { oversized_image: 'error' }`, so a model that would downscale them (standard-res tier) is rejected with a Norwegian error instead of misplacing crops. So `CLAUDE_MODEL` must support high-res vision, adaptive thinking and effort; the Opus/Sonnet/Haiku 5.5 models do (Haiku 5.5 is high-res, unlike Haiku 4.5). Check a cheaper or older model against these before suggesting it.
  - Usage log (`src/usage.ts`): `buildApp` wraps the AI service in `MeteredAi`, which writes one `usage_log` row per call (also failed ones: errors raised after the model answered carry `ConversionError.usage` via `withUsage`). What a call belongs to (user, note, deck, subject, pages) comes from AsyncLocalStorage: background jobs (converter, flashcard generator, comparison) open a fresh `jobScope({ userId: row.user_id, … })` that does not inherit from the request that kicked the queue, request-bound calls (TOC routes) use `usageScope` with the request user's id, and the converter sets the real page count with `setUsagePages` once the pages are rendered (a new note's `page_count` is the number of files until then). `GET /api/usage?days=` summarises cost at list price (`MODEL_PRICES`, `USD_NOK`, local/fake = 0); shown in Settings → «Forbruk av AI». Server-only table, not synced.
  - Backup (`src/backup.ts`, `routes/backup.ts`): `GET /api/backup` streams a `.tar.gz` (own ustar + pax writer, gzip level 1) with a consistent DB copy (`Repo.backupTo`: SQLite backup API, sessions, devices, reset links and unused invites removed with `secure_delete` and a `VACUUM`, so they are not left in free pages, `journal_mode = DELETE`), `LES-MEG.txt` (restore steps: stop server, delete `-wal`/`-shm`, swap in DB + `notes/`), a `sikkerhetskopi.json` manifest and every file under `notes/`, hard-linked into `tmp/backup-*` when the request starts so deletes/edits/reconverts during the download don't change the archive (not `bundles/`, `tmp/` or `*.tmp`; a new data folder must be added to the archive). That only holds if files under `notes/` are never rewritten in place: write them with `writeFileAtomic` (`storage.ts`) or rename, never plain `fsp.writeFile`. `meta.last_backup_at` («Sist sendt fra serveren») is set when the response finishes, which is not proof the device saved the file; no HEAD route (it would snapshot for nothing). `GET /api/backup/status` feeds Settings → «Sikkerhetskopi», which polls until the download is done. Restore is not built yet (Railway volume backups need the Pro plan); after a restore the server's `rev` is lower than the devices' cursors, and `pull()` in `web/src/sync.ts` then replaces all local rows instead of keeping «newer» ones, and clears cached PDFs (a `pdfRev` can mean other content after a restore). The Docker entrypoint chowns `/data` when any file there is not owned by `node`.
  - Model comparison (`pipeline/compare.ts`, `routes/compare.ts`): «Prøv med Haiku» re-converts a finished note with `COMPARE_MODEL` (`claude-haiku-5-5`, a bare metered `AnthropicClaude`, deliberately without `RefusalFallback` so a refusal never shows a Sonnet PDF as Haiku's; tests pass `compareAi`). `Comparer.start` sets the row to running before its first `await`, copies `pages/` into `tmp/compare-*`, then runs one at a time: `Converter.buildConvertRequest` (same input as the real conversion), `cropFiguresInto`, `compileInto` (same template and title block via `docInfo`) and the same fix loop, and finally swaps the result into `notes/<id>/compare/haiku/` with a rename (no recursive mkdir, so a note deleted meanwhile is not recreated). It never touches the note row, its files, `rev` or sync. Server-only tables `note_comparisons` (one row per note with the `prompt_version` it was made with; running rows are marked failed on restart instead of re-run, since it costs money) and `comparison_ratings` (rating `haiku_ok`/`sonnet_better` + comment per note and instruction version, so Settings counts only ratings of the current version and lists older versions separately). Usage is logged under the note via `usageScope`. Precise rules (`profiles/precise.ts`, made for Haiku in version 2, for every Claude model since version 3): `systemPromptFor(profile, model)` appends the subject's `preciseRules` (section 7: latex before metadata, named formel boxes, merknad only for certain errors, `\uleselig` only when the context leaves two readings, `samlet` around calculations, drawing templates per subject (physics TikZ/pgfplots/circuitikz, chemistry `\ce`/chemfig/energy diagram/titration curve, biology crossing scheme/flow/cycle, geoscience climate diagram/terrain profile/layer sequence/cycle; templates use no colour), a full example answer, checklist) for every `claude-*` model (`usesPreciseRules`); Ollama keeps `profile.systemPrompt` alone. Only Haiku ends `convert` with `HAIKU_CLOSING` (`usesHaikuClosing`); Sonnet/Opus end with `CLOSING`, and Sonnet keeps `effort: medium`. Each «replaces "…"» in the rules must quote the base prompt verbatim (tested). The comparison runs Haiku with `COMPARE_EFFORT` high, `COMPARE_MAX_TOKENS` 128 000 and at least `COMPARE_FIX_ATTEMPTS` 3 fix rounds. Changing any of these (or the rules or closings) means bumping `PROMPT_VERSION` and the fingerprint in `test/precise.test.ts`, which also compiles every template and the example answer per subject. A comparison still rates Haiku; the note's own version has the rules only if it was converted after version 3. Web: menu item on the note page → `/notat/:id/sammenlign` (`ComparePage`), summary card in Settings (`GET /api/compare/summary`).
  - Subject profiles (`SubjectProfile` = `physics` | `chemistry` | `biology` | `geoscience`): `src/profiles/<id>.ts` (system prompt – keep it free of dates/ids so it caches; `tocPrompt` via `toc-prompt.ts`) + `latex/<id>/preamble.tex` (physics «Klassisk», chemistry «Moderne» with mhchem/chemfig, biology «Lærebok», geoscience «Atlas» with pgfplots and patterns). Register new ones in `profiles/index.ts`, `shared`, `precise.ts` (`DRAWINGS` and `DRAWING_CHECK`, bump `PROMPT_VERSION`), the fake TOC/body in `claude.ts`, `web/src/lib/subjects.tsx`, `lib/theme.ts`, the early theme script in `index.html`, `styles/subjects.css` and `viz/registry.ts` (`[]` when there are no visualizations).
  - Subject presets: `src/presets.ts` (`SUBJECT_PRESETS`: LK20 competence aims from Udir (public, NLOD) plus SmartNotes' OWN topics → subtopics → aims; no textbook names or textbook tables of contents, for copyright reasons; users import their own book's TOC privately). Old ids (`ergo-fysikk-1` …) are `aliases`, so a DB seeded with them is not seeded again; `findPreset` resolves them. `SEED_TEXTBOOKS` (comma list, default `DEFAULT_SEED_PRESETS` = physics, chemistry, biology; `none` = blank «Fysikk») seeds each preset once (meta key `seeded_presets`), also into an existing DB. A new preset (Geofag 1, `geofag-1-lk20`) must never be added to `DEFAULT_SEED_PRESETS`, or it would appear for existing users; users add it with «Legg til fag» (`GET /api/presets`, `POST /api/subjects/from-preset`, `Repo.addPreset`, which also marks it seeded). Sections live as JSON on `chapters.sections`, aims on `subjects.aims`; a note stores only its section code, and its aims are derived from the section. Claude picks chapter + section; the server validates the section against the chapter.
  - Table of contents import (`src/toc.ts`, routes `/chapters/parse|extract|bulk`): text or photos → chapters with sections; Claude maps sections to the subject's aims (`mapSectionAims`, or inside `extractToc`). The web preview (`pages/settings/ChapterImport.tsx`) updates existing chapters (same number) instead of duplicating them.
  - `notes.search_text` = `latexToText(body)`, synced to the client for offline search.
  - LaTeX safety: compile with `latexmk -no-shell-escape`, `openin_any=p`, `openout_any=p`; `sanitizeBody` strips file/preamble commands.
  - Normalizer (`normalizeBody` in `latex.ts`, run by `sanitizeBody` for every model, outside TikZ/circuitikz code): `35 %` → `35\,\%` (a bare `%` silently drops the rest of the line), `løsning` → `losning`, a title on husk/merknad/losning moves into the box, a repeated «Eksempel:»/«Oppgave»/«Definisjon:» is stripped from titles, figure/table get `[H]`, blank lines inside display math are removed, `\caption` in a free-standing center block becomes `\captionof{table}` (tabular, no drawing) or `\captionof{figure}` (floats, also inside a center block, are left alone), and `\uleselig` inside a number argument of a siunitx command (`ULESELIG_HOSTS`: `\qty`, `\num`, `\ang`, ranges, lists) or inside `\ce`/`\pu` is moved out around the whole command (siunitx rejects it; mhchem would set it in italics), while a `\qty`/`\num` whose number is `[uleselig]` or `?` becomes `\text{…}\,\unit{…}`; a unit with æ, ø, å or ° inside `\qty`/`\SI`/`\unit`/`\si` (siunitx drops them) is rewritten (`°C` → `\degreeCelsius`, `°` → `\degree`, otherwise `\num{N}\,\text{U}` or `\text{U}`); verbatim/`\verb`/lstlisting/minted are passed through like drawings (and kept as text in `latexToText`). Only patterns that never compile or print right are touched; keep it that way (tests in `unit.test.ts`). `EXTRA_PREAMBLE` (also used for chapter/subject bundles, so it must keep every stored note compiling) adds `samlet` (the block is typeset once, as it would be inline, into a `\vbox` with the list's `\parshape` restored, then measured: a short block becomes one unbreakable `\vtop`, a block taller than 0.85 `\textheight` is `\unvbox`ed so it breaks normally; when the block opens with a list or trivlist inside a box, a one-shot `\@trivlist` hook carries the outer `\prevdepth` in so the first line keeps its baselineskip (text- and display-first blocks get their interline glue outside the box, where page and box breaks can discard it), and `\tcbset{break at=\textheight}` stops a breakable tcolorbox inside the block from splitting against the stale page state; footnotes go under the block as in a minipage, or to the enclosing box; the trailing display skip and `\prevdepth` are carried out. Do not turn it into an argument-grabbing `+b` environment: that broke `\verb`, verbatim, babel's `"` in TikZ labels, nested counters and error line numbers; tests in `samlet.test.ts`), a math-safe `\uleselig` (extra group so `\uleselig{v}^2` works), Norwegian number format for pgf/pgfplots (`use comma`, thin-space 1000 separator from five digits, like siunitx) and English aliases (`solution`, `definition`, `example`, `exercise`). `errorExcerpt` shows the whole samlet block when LaTeX reports an error on its `\end{samlet}` line. `parseMeta` repairs LaTeX in metadata strings instead of dropping all metadata (and with it every figure): when JSON.parse fails, lone backslashes are doubled (also `\u` without four hex digits and `\b\f\n\r\t` before a letter, as in `\theta`); after parsing, `repairLatexEscapes` restores control characters in math and tab/CR before a letter everywhere (one-line fields).

## Commands
- `npm test` (server vitest, needs TeX Live incl. `texlive-plain-generic` for chemfig, + poppler; plus web vitest for the viz models), `npm run typecheck`, `npm run build`, `npm run test:e2e` (Playwright, Chromium desktop + mobile), `npm run test:e2e:webkit` (Safari/iPad, own CI job). `test:e2e` runs the built `server/dist` + `web/dist`, so run `npm run build` first.
- Fresh container: TeX Live is not preinstalled. Before `npm test` run `sudo apt-get update && sudo apt-get install -y --no-install-recommends texlive-latex-base texlive-latex-recommended texlive-latex-extra texlive-science texlive-pictures texlive-plain-generic texlive-lang-european texlive-fonts-recommended lmodern latexmk poppler-utils` (same list as `.github/workflows/ci.yml`).
- Deploy: Railway (`railway.json`, Dockerfile, volume on `/data`, variables `APP_PASSWORD`, `ANTHROPIC_API_KEY`, `PORT=8080`, auto-deploy from `main` with Wait for CI). Step-by-step for the user: `docs/OPPSETT.md`; Fly.io/Docker alternatives in `docs/DEPLOY.md`. The image starts as root only to chown the volume (`scripts/docker-entrypoint.sh`), then runs as `node`.
- Dev: `SMARTNOTES_FAKE_CLAUDE=1 npm run dev` (server :8787, web :5173 with /api proxy).
- Mutating API calls require header `X-SmartNotes: 1`; auth is the `sn_session` cookie (owner: `APP_PASSWORD` with an empty username). The auth hook in `auth.ts` decides by the matched route (`req.routeOptions.url`), never the raw URL, because the router decodes `%61pi` to `api`.
